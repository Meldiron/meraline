# AGENTS.md

Meraline is a macOS 26 menu bar app for quick, ephemeral AI chats: press ⌥ Space, ask, read the streamed answer, let it go. Swift 6, SwiftUI plus AppKit, no sandbox, hardened runtime. This file is the entry point for agents and contributors; [CONTRIBUTING.md](CONTRIBUTING.md) is the human-facing version.

## Build, test, run

The Xcode project is **generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)** from `project.yml` and is gitignored. Re-run `xcodegen generate` after adding or removing files; every script does it for you.

```sh
scripts/dev_run.sh                  # Debug build, relaunch from DerivedData, logs in /tmp/meraline.log
scripts/test.sh                     # full test suite (Swift Testing), xcbeautify output when installed
scripts/test.sh HistoryTests        # one test struct
scripts/test.sh --e2e               # also run the installed claude, codex, and opencode for real
scripts/install.sh                  # clean Release build into /Applications and launch it
scripts/clean.sh                    # remove build/ and DerivedData
scripts/showcase.sh                 # pictures of scripted scenes (games, Settings panes), dark and light, while you work
scripts/screenshots.sh --wait-idle  # README screenshots that need a real provider, an agent, or clicks, once the Mac is idle
scripts/release.sh 1.2.0 --adhoc    # the whole release pipeline without credentials (see docs/releasing.md)
```

Dependencies are pinned to exact versions in `project.yml` (Sparkle, KeyboardShortcuts, EventSource). Bump them there, deliberately.

A Developer ID certificate is optional. `dev_run.sh`, `test.sh`, and `release.sh --adhoc` sign ad-hoc when the certificate is missing; only `install.sh` and real releases need it. When it is there, don't force ad-hoc signing (`CODE_SIGN_IDENTITY=-`): macOS treats every ad-hoc build as a new app, so a build that runs asks for the Keychain password and loses Accessibility access each time. The test host never starts the app (`MeralineApp.isHostingTests`), so tests don't read the Keychain or take the shortcut, however they are signed.

## Commits

Commit as you go. Every change that is done and passes its tests gets its own commit right away, so the history reads as a list of what changed, one step at a time. Don't leave finished work uncommitted at the end of a session, and don't save a day of work for one big commit.

- **One change per commit.** A feature, a fix, a refactor, a batch of screenshots, or a docs pass is each its own commit. The code, its tests, the docs it changes (README, AGENTS.md, `docs/`), and its bullet under `## Unreleased` in CHANGELOG.md go in together. Every commit builds and passes `scripts/test.sh`.
- **Say what changed, in plain words.** The subject is one line, in sentence case with no prefix and no final period, that says what the change does for someone using Meraline or working on it, the way the changelog would: "Agents hand files over with present_files", "Fix the window not moving on macOS 27". Keep it under about 70 characters. When the reason isn't obvious from the subject, add a body after a blank line.
- **Commit only your own work.** Several sessions often edit this checkout at once. Stage what you changed by path (`git add <path>`; never `git add -A`, `git add .`, or `git commit -a`) and read `git diff --cached` before you commit. When a file you changed also holds another session's unfinished edits, stage only your hunks (save `git diff <path>` to a patch, cut it down to yours, and `git apply --cached` it), or wait until theirs are committed.
- **Commit on `main`, push when asked.** Never amend, rebase, or force-push a commit that has been pushed or that another session made.
- **Never commit** `SESSION_NOTES.md`, `research_notes/`, or `reports/` (they are in `.git/info/exclude`), `build/`, or the generated `Meraline.xcodeproj`.

## Hard rules

- **Nothing on disk.** Conversations, drafts, images, and recent chats stay in memory. Do not add persistence for them. The one folder an agent gets is the chat's workspace (`ChatWorkspace`, an empty temporary folder per chat): it holds only the files and folders you attach and what the agent writes there, and goes with the chat (when its time runs out, it is deleted, or it leaves Recent Chats, not on Esc) or at quit. At most `ChatSession.chatLimit` (1,000) chats are in memory, the open one included, so Recent Chats drops its oldest, workspace and all, past 999; a chat takes at most `ChatSession.chatByteLimit` (512 MB, pictures mostly), and a question past it stays in the input; a workspace takes in at most `FileAttachment.folderLimit` (20,000) files and folders from attachments, counting what is there already. macOS clears old files out of the temporary folder: a workspace found missing is made again, empty, its live agent ends, and the next question carries a warning (`Turn.notice`). An attachment is copied in when its question is sent; until then the draft keeps only its path. A file the agent hands over stays in the workspace; only Save to Downloads, which you click, writes anywhere else. The one other thing kept on disk is the usage ledger (`UsageLedger`, `~/Library/Application Support/Meraline/usage.json`): counts by five-minute slot of questions, answers, tokens and cost by model, games, their rounds and runs of wins, and each game's own numbers (`GameFigures`: scores, words' lengths, puzzles solved), agents' tools and asks, and what was done with answers, so Settings can show usage by the hour, day, week, month, and year. It holds no question, answer, title, model reply, or file name, only numbers and the names of providers, models, games, games' numbers (`GameStat`), and rewrites; `ChatSession` counts through its `usage` (`UsageLedger.shared` in the app, one in memory in tests), a token count the provider reports (`Turn.usage`) or else an estimate from length, and anonymous chats count like any other. Never put text into it.
- **Secrets go through `SecretStore`.** API keys are Keychain items; never put them in UserDefaults, logs, diagnostics, or URLs.
- **Log through `Log`, never `print`.** `Log.<category>.info(...)` writes to `os.Logger` and the in-memory buffer that feeds the diagnostics report. Log providers, models, paths, and error descriptions; never questions, answers, or keys.
- **Swift 6, strict concurrency, `MainActor` by default.** Networking and parsing types are `nonisolated`. Sparkle's KVO and delegate callbacks must read their arguments rather than main-actor state.
- **Design.** The base is neutral glass: white, black, gray, graphite accent. Pink appears only as an accent (text cursor, the sparkle in the input row, toggles, the active pin, a faint glass tint on buttons). Never solid pink buttons or strong pink backgrounds. Never rotate a view that has glass on it: glass in the panel's container swells into a disc beside its place while it turns. Rotate the symbol inside instead (scaling glass is fine). The logo is the sparkle character with a face; do not change it. The panel draws its own rounded shadow and keeps the window shadow off. Its SwiftUI content is laid out at a fixed height, pinned to the window's top (`PanelController.sizeContent()`), and the window only shows as much as the card needs: it grows at once and shrinks after the card's animation. Don't make the hosting view the window's content view again; a window resize would then resize the layout mid-animation and drop the card by half its growth.
- **Behavior.** Return or Tab sends. Esc puts away the shortcut picker, closes a panel of actions (or backs out of its confirmation), folds away the What's New notes, stops, then starts a new chat, then closes. Closing the window only hides it. Every chat has its own time, `ChatSession.chatLifetime` (30 minutes, no setting): a message, the end of an answer, or a click on its timer starts it over, and a game waiting for its first move has none yet. It keeps running in Recent Chats, and reopening the chat keeps the time it has left (a chat already out of time goes instead). When it runs out, the chat goes with its workspace without passing through Recent Chats; what is typed in the input stays, and an answer still coming holds the open chat until it ends. `ChatSession.expireChats(now:)` does it, at each deadline and when the window opens, in case the Mac slept through one. The timer (`ChatTimer`) is a neutral glass capsule under the card's bottom right, lined up with the footer's actions, in the same bottom margin as the capsules on the left: minutes left, then seconds in the last one. From "5 min left" (`ChatTimer.warningMinutes`) it looks like the mode toggle's chosen segment: a pink symbol and a semibold label in the primary color, in glass with the same faint pink tint. Before there is a chat (no turns and no game), the same spot can hold two pills instead (`CostNudges`): what LLMs and what agents have cost today, the calendar day's cost in the usage ledger (`UsageLedger.cost(of:onDayOf:)`), each once it passes the amount set in Settings › Usage › Daily nudge (`Preferences.costNudges`, off for both until set, kept in UserDefaults). They are neutral glass with a pink symbol, and take no click, so the timer is never one of two buttons on that spot while one fades into the other, even in the hidden window when a chat runs out. The pin has no countdown, and Settings › General › Start a new chat was removed on purpose; don't bring them back. Capsules under the card's bottom left, lined up with the buttons above its top left (`Announcements`, drawn in the window's bottom margin, which is `Announcements.roomBelow` taller while one shows), announce updates and a crash. A capsule whose state changes, the update's from found to staged, the crash's from Copy Diagnostics to Copied, is one view whose label changes, never one view for each state: two of them cross-fading while the window was hidden hung Meraline for good on macOS 27, two focusable buttons on one spot that SwiftUI's key view loop never settled over, and `AnnouncementsTests` lays the real panel out under a watchdog to keep it so. After Meraline quits unexpectedly, the next launch finds macOS's report of it in ~/Library/Logs/DiagnosticReports (or its Retired folder), newer than the launch before (`CrashNotice`, which keeps only the launch date in UserDefaults), and a Copy Diagnostics capsule copies the report with a Crash section, says Copied, and goes; its cross hides it too, and the next launch never offers the same crash again. The section keeps only the exception, the termination, the Swift runtime's words up to their first colon (none if they quote something) or an uncaught exception's name (never its reason), Meraline's image UUID and load address, and the crashed thread's frames, so the diagnostics still hold no question, answer, or key; Settings › About › Copy Diagnostics includes it for the rest of that run. The sparkle's panel offers Copy Diagnostics at any time, crash or not, through the same `CrashNotice.copyDiagnostics(of:preferences:updates:)`, and the crash's capsule then shows only to say Copied: one capsule whose label changes, never a second one. Before any copy, `Diagnostics.redacting` writes the home folder as `~` and takes out any API key set in Settings, across the whole report, log lines included. After an update, What's New opens the notes under the input, with their screenshots (`ReleaseNotes.Block.picture`, fetched when the notes open through an ephemeral session and kept in memory), until its cross or Got It hides it; `WhatsNew` keeps the version and Sparkle's notes in UserDefaults so the next update brings it back, and there is no What's new window. Beside it, an update Sparkle found (Update Available, which opens Sparkle's window) or staged (Restart to Update) shows until its cross hides that version; `UpdateNotice` keeps the hidden version in UserDefaults, so only a newer update brings it back. The menu bar item and Settings › Software Update offer the update regardless. On the first launch the window opens on a shortcut picker (`ShortcutSetup`, until `hasChosenShortcut` is set) before the shortcut is ever pressed: it checks whether macOS uses ⌥ Space, whether Meraline could register it, and whether ChatGPT, Gemini, Copilot, Raycast, Alfred, SpotAsk, or Seer is running or installed, then offers Keep or suggestions that skip whatever looks taken. A suggestion is registered under `shortcutTrial` until it is pressed, which keeps it, or Use This Shortcut. Esc or a click elsewhere keeps ⌥ Space and leaves a capsule under the empty input that opens Settings › General on the recorder, until the shortcut changes or its cross hides it. The row under the input (`ModeBar`) holds the LLM and Agent toggle on the left (⌘1, ⌘2) with the privacy badges beside it and, on the right, the games behind a controller and Recent Chats behind a clock that shows their count. The controller opens and closes the games; one tray is open at a time, and `PanelLayout` remembers which while the window is hidden, in memory only. `GameTray` lays out every frame of its spring from one animated `openness` (the capsule's width, how much of the row shows, each game's fade), so nothing is inserted or removed while it moves; keep it that way, since inserted views land ahead of the glass. The footer under a chat shows one primary action (Stop, Copy Answer, or a game's Hint or End Game) and Actions ⌘K; the rest live in a panel of actions, as do the sparkle's providers and the clock's recent chats. Beside Ask Again, the chat's panel rewrites the last answer (`ChatSession.rewrite(_:)`: shorter, longer, simpler, more concrete, a bullet list): the provider in use gets the conversation and the rewrite's instruction, and the new answer takes the old one's place under the same question, so follow-ups and the next rewrite read it; the instruction never shows. A rewrite stopped or failed partway puts the old answer back. Under a chat's finished answer (not a stopped one, nor a game's move), two or three follow-ups (`ChatSession.followUps`) show while the input is empty: a click puts one in the input, a Shift-click asks it, and while Shift is down the capsule under the pointer shows an arrow. `FollowUps` works them out on this Mac, never through the provider: Apple's on-device model when Apple Intelligence is on, else rules drawn from the answer's code, its terms in bold, and the kind of question, in English only. They are in no turn, so Recent Chats never keeps them; every request clears them and a reopened chat gets new ones. They fade in and go at once, so an old set never lies under a new one. The three panels are one component (`ActionPanel`) drawn inside the window over the card, with a search field, arrows and Return, and keycaps. The chat's and the clock's open up and to the left of their buttons; past the card's top, the window raises its own top (`PanelController.fit(height:roomAbove:)`) so the card never moves on the screen, and only when the screen has no room above do they open downward. The sparkle's opens down and to the right. An action that can't be undone (Delete Chat ⇧⌘⌫, Clear Recent Chats) confirms inside the panel, never with an alert or sheet, because the window closes when it loses the keyboard. Insert Answer (⌘↵, `AnswerInserter`; the shortcut steps aside while the input has text) closes the window, which hands the keyboard back to the app in front since the panel never activates Meraline, and pastes the last answer at its cursor through that app's Paste menu item, or ⌘V when it has none that reads enabled; the answer sits on the clipboard marked `org.nspasteboard.TransientType` and the clipboard is put back after, unless something else was copied meanwhile. Without Accessibility access it only copies. It is not offered when Meraline itself is in front. Tear Off Answer (⌘T) opens the last answer in a floating glass note (`AnswerNotes`, in memory only), beside the window: it moves by its header or empty space, resizes from its sides and bottom (it fits its answer until then), folds its question away, and draws its shadow as a layer of its own behind the glass, since a shadow on glass shows only while its window is key. Answers zoom for reading across the room (`AnswerZoom`, 85% to 300%): ⌘+ (⌘= too), ⌘−, and ⌘0 from the chat's actions, or a pinch anywhere over the window, which `FloatingPanel.sendEvent` hands to `PanelController` before any view sees it; a pinch settles on a step it ends near. Only the answers' Markdown grows, its text, code, tables, and the room between them, through the environment's `answerZoom`, which `MarkdownView` reads; questions, cards, and the rest of the window keep their size. The window's zoom (`PanelLayout.answerZoom`) is one for every chat, in memory until Meraline quits, and while it isn't 100% a capsule in the footer (`AnswerZoomBadge`) shows it and goes back to actual size. A torn-off note opens at the window's zoom, then zooms on its own, by a pinch or by ⌘+, ⌘−, and ⌘0 while it has the keyboard, and widens with it until you resize it. Borderless windows move through `WindowDragArea` behind their content, not `isMovableByWindowBackground`, which stopped moving them once SwiftUI took the click. The chat's shortcuts (⇧⌘C, ⌥⇧⌘C, ⌘↵, ⌘T, ⌘R Ask Again, ⌘N, ⇧⌘O, ⇧⌘⌫, ⌘+, ⌘−, ⌘0, and a game's ⌘I and ⌘R, which is Play Again once a round is over and otherwise restarts the game, the game so far going to Recent Chats as when any game starts) are matched by `PanelController`'s key monitor against `PanelContext.chatMenu`, so they work with or without a panel open. With no chat open, ⌘S is Stash Draft (`ChatSession.stashDraft()`, `PanelContext.stashDraft`, also at the top of the clock's panel): the draft, what is typed and the texts, clipboard text, images, and files added, goes to Recent Chats as a chat of its own (`PastChat.draft`, no turns, no workspace) with its own `chatLifetime`, the input empties, and the clock's capsule says Stashed for a moment. Reopening it puts it all back in the input, where it has no time, like anything typed; a draft in an empty chat when another chat reopens is stashed the same way, so it is never lost. A chat's follow-up, a game, and anonymous mode stash nothing. Shaking the window while dragging it (`ShakeDetector`, fed by `windowDidMove`) forgets the recent chats like Clear Recent Chats, without asking, and the clock's capsule says so for a moment; the panel does not mention the shake. Each mode keeps its own provider (`Preferences.mode`, `defaultProvider(for:)`), and the sparkle's panel lists only the ready providers of the current mode; there is no model switcher in the panel, and Recent Chats are not in the sparkle's panel. The sparkle's panel also turns anonymous mode on and off, as does ⇧⌘N (`ChatSession.isAnonymous`, in memory only and never saved): whatever chat is open when it ends skips Recent Chats and its workspace goes with it, the sparkle goes graphite with sunglasses cut out of it (`SparkleIcon`, drawn from the app icon's sparkle), and the input asks "Ask anything secretly…". Games are a mode of `ChatSession`, started from their buttons in that row. A round can wait for someone to open it (`GameState.Phase.opening`, and `.over` for the next round, both with a `GameOpening`): what you type opens it (`GameRules.open(with:after:)`, a turn with the game's cue for your opening and your line), and Return with nothing typed, the button on the invitation card (`GameOpening.button`, always a random one: Random Rhyme, Random Word, Random Category, Random Puzzle, Random Sentence; `NudgeRow` draws it, and the card shows the game's invitation while the round waits), or Play Again leaves it to the other side (`GameRules.opener(after:in:dice:)`): the model, asked with a cue, or a move this Mac drew, kept as the model's reply to the cue without asking it (`GameOpener.drawn`). In Rhyme Duel whoever opens sets each rhyme and the other answers it, so when you open, the model answers every line of yours and has the last word. The duel's last reply rates how you played (`RhymeDuel.Rating`): “Score: N/10 — ” and one thing to do better next time, quoting your words, under the model's closing line, or alone when the closing line is yours, which goes to the model for it (`RhymeDuel.rateTheDuel`); a rating the model forgets ends the duel all the same. The score shows in the transcript, the footer, and the rematch tray, never in Copy, which takes the poem. In Categories you name the category or take a random one, and the model always names the first thing in it; your sixth thing goes with an aside that it is the last, so the model only judges it. In Add-a-Word you type a sentence's first word, or this Mac draws one (`AddAWord.starters`), kept as the model's, and you add the next. From the second sentence on, the first move of each that goes to the model brings the finished sentences written out (`AddAWord.storySoFar`), since the turns before hold them one word a message. In Word Football you kick off with a word, or this Mac draws one (`WordFootball.kickoffs`), kept as the model's. In Odd One Out you set the first puzzle or the model does, and whoever set it sets every other one. In Fix the Typo you choose again before each of a game's five sentences (`GameState.Phase.opening` between them): type one with a typo, which the model hunts for and you judge with It found it or It missed, or leave it to the model, which writes one for you to fix; each sentence goes to whoever won it (`FixTheTypo.Score`). In Speed Definitions the side that opens keeps it for the whole game: you give every word and judge the model's definitions, or the model shows them all. Only Longest Word always starts at once: this Mac draws each round's nine letters (`LongestWord.draw`), the model picks its word first, hidden until yours is in, and this Mac judges both words (`WordCheck`: macOS's spell checker, in the language the round's aside names; a word of yours it doesn't know counts when sent again), then shows a longer word from its word list when it knows one. A round takes one trip to the model. A game's rules work everything out from the turns, so a game keeps no state of its own; answers the model hides after a `|` in its reply stay hidden until you have played, except that Hint in the footer shows a game's hints for your move one at a time (Rhyme Duel's list the rhymes the model hid for its last word and the rest of that word's family, `RhymeDuel.hintWords` to a hint; Longest Word's, what this Mac's word list knows of the longest word in the letters). Whatever should change from one game to the next is drawn on this Mac (`GameDice`), never left to the model: asked the same thing, a model picks the same way however it is told to pick at random. Rhyme Duel draws each duel's story (someone, somewhere, something happening, a mood) and, for each of the model's lines, three words of one rhyming sound (`RhymeDuel.families`) that no line of the duel has ended on, nor of the chat's earlier duels while sounds are left. Word Football draws a kind of word (`WordFootball.kinds`) for each word the model plays. Categories draws a round's category (`Categories.categories`), none the chat has played while others are left, when you don't name one. Odd One Out gives each of the model's puzzles a theme (`OddOneOut.themes`), one the chat hasn't had while others are left, and a way to link the two that belong. Speed Definitions draws a difficulty (`SpeedDefinitions.Difficulty`: medium three times in five, else easy or hard, shown in the word's heading) and deals the model three words of it to pick from, none the chat has played while others are left. Longest Word draws each round's letters from a weighted bag, three or four vowels, again until this Mac knows a word of six letters in them. The lists are English, so in another language (`AnswerLanguage`, passed to `aside(for:after:in:dice:)` and `opener(after:in:dice:)`) a game draws only what the model can take in it: Rhyme Duel its story, not words to end on (its hints and rhyme check then use the model's own rhymes, since family words count only when they were offered); Word Football and Add-a-Word have the model start, with a drawn kind of word or subject; Categories has the model name the drawn category in the language before a bar in its first reply; Speed Definitions asks for a word of the drawn difficulty on a drawn topic; Longest Word draws its letters all the same and checks words with the spell checker for the language when it has one, with no hints or longer word. Rhymes and Word Football's letters ignore accents, and Longest Word spends an accented letter as its plain one. What was drawn goes after the move as the turn's `aside` (`GameRules.aside(for:after:dice:)`), which the transcript never shows and the turn keeps, so the conversation Meraline sends back matches the one a live agent remembers. Each game sends its own system prompt instead of the LLMs' or the agents', lives only in memory like any chat, and Esc or End Game ends it. A move that breaks the rules comes back to the input and costs nothing. A round that ends says who won it (`.over(outcome:rematch:)`), and `ChatSession.versus` counts each game's rounds against the model; the rematch tray (`RematchTray`) shows that tally with Play Again (⌘R) under the transcript once a round is over, and stays on the empty panel after the game until a new game or its cross. The tally and the tray are the one game state that outlives a chat, and they live in memory only, so quitting forgets them.
- **Attachments.** Dropping or pasting (⌘V) attaches an image, which works in either mode, or any other file or a folder, which only an agent reads: the prompt names it and the agent finds a copy in its working directory, a subfolder for a folder. The agent starts one level above a copied project on purpose, so the project's own agent settings (hooks, `opencode.json`, `.mcp.json`) never load by themselves. A folder in git brings what `git ls-files --cached --others --exclude-standard` lists, plus `.git` at a repository's top; any other folder comes whole; either way at most `FileAttachment.folderLimit` files, and never a disk or the home folder. In LLM mode an attachment waits in the draft under a row with Switch to Agent, and Return does nothing until you switch or remove it. Games take neither.
- **Selected text and files.** The shortcut reads the frontmost app's selection before the panel takes the keyboard (`PanelController.toggleBringingSelection`): through Accessibility first (selected text, or else the selected items of a file browser, whose `AXURL` names the file, as Finder's do), and for an app that doesn't answer, by pressing the ⌘C item in its own menu through Accessibility and restoring the clipboard. Only an app whose focused element is its window, so it describes none of its content (Zed), gets a posted ⌘C, with the key that types C in the current layout and only when its menu item is missing or reads disabled; other apps never get a keystroke, so nothing beeps. A copy that VS Code (`isFromEmptySelection`, inside Chromium's `org.chromium.web-custom-data`) or Zed (`is_entire_line` in `zed-metadata`) marks as a line copied from an empty selection counts as nothing selected. It never reads Meraline, password fields, or under secure input. Selected text never joins the question by itself: the shortcut only offers it (`ChatSession.offeredSelection`, withdrawn when the window closes), and the selection button above the card adds it to the draft (`toggleOfferedSelection()`). The button can't read the selection itself, because by the time it is clicked the panel has the keyboard. Once added, each text waits in the draft (`draftSelections`, as many as you add) in a card of its own between the input and the `ModeBar`, goes with the question as a `<selected_text from="App">` block, in order, and stays with the turn as a quote (`Turn.selections`): the app, its word count (`SelectedText.lengthLabel`), and two lines of the text, which its header opens in full and folds back when they cut it short. Both the quote and the draft's card find out whether their lines cut anything by laying the text out hidden behind itself (`QuoteText`), so the chevron only shows when there is more to see. The Services menu (`NSServices` in project.yml) and `meraline://ask?selection=` bring it without Accessibility access. So does a drag: text dropped anywhere on the card, the input included, joins the draft as a card of its own, named after the app in front, which is the one it came from (`SelectedText.handedOver`, as the Services menu names it); `ClipboardContent.drop(of:)` tells a dropped item's text from a file or picture, and a web page's picture, which drags its address along as text, stays a picture. The input's field editor, SwiftUI's own, would take a drop itself, so `FloatingPanel` takes its drag types off after each focus and when the window gives up the keyboard. Don't hand SwiftUI a field editor of Meraline's instead: its text field crashes on any other class. The Services menu also takes a picture, as Preview hands over a selected image (TIFF) and other apps their own image data, and attaches it as an image in either mode, once however often the same picture comes (`ChatSession.bring(_:)`); `ClipboardContent.readSelection(from:)` reads what it is handed as the clipboard button reads the clipboard, except that text wins over a picture whatever the app listed first, so a selection that is both stays words. Finder files go through `ChatSession.bring(files:)`: photos in either mode, anything else, folders included, only in Agent mode (the Services menu brings everything, like a drop), and each press of the shortcut takes exactly what is selected then (`bringCurrentSelection`): files replace what an earlier selection brought and text replaces the offer, and nothing selected takes both away, while anything added by hand, the draft's text included, stays. ⌫ in an empty input takes out the last text, then the last attachment, and ignores key repeats. Games ignore both. Only the on/off setting and whether the hint was dismissed live in UserDefaults.
- **Selection, clipboard, and screenshot.** Three glass circles float above the card's top left, lined up with the sparkle (`ContextButtons`, drawn in the window's top margin, which is `ContextButtons.roomAbove` taller for them). Context adds up: every click adds what its button has now, so texts from several apps, several copies, and a screenshot per visit can all go with one question. A click takes out instead only when that exact version is in the draft already: the same selected text (`SelectedText.isSame(as:)`), the same clipboard copy (by `NSPasteboard.changeCount`), or the same visit to the screen (`ContextSources.screenVisit`, which moves when the window opens, the app in front changes, or the window changes screens). `ContextSources` (owned by `PanelController`, in memory) remembers which draft items came from which copy or visit; ⌘V's attachments count as the clipboard's. Each button has three states (`ContextButtons.Status`): unavailable, faded and disabled (no text offered, nothing addable on the clipboard, or the draft at `ImageAttachment.limit` images); available, neutral glass; and added, the active pin's pink symbol and faint pink glass. Don't collapse them. The selection button (⇧⌘E, a text cursor at the end of a highlight, drawn by hand in `SelectionIcon`) toggles the offered text (`toggleOfferedSelection()`). The clipboard (⇧⌘V) reads `NSPasteboard.general` through `ClipboardContent`: copied files attach as ⌘V attaches them, a picture as an image, and text goes to a card of its own as `SelectedText.clipboard` (`isFromClipboard`), which the model reads as a `<clipboard>` block; with both a picture and text, the kind the copying app listed first wins. While the window is up, `ContextSources` looks at the change count every 0.75 s, and at the clipboard's kinds (never its contents) when it moves; anything a password manager marks `org.nspasteboard.ConcealedType` or `TransientType` is never read. The screen (⇧⌘S) takes one picture of the screen the window is on with ScreenCaptureKit, leaving out every Meraline window (`SCContentFilter` excluding Meraline's own app), and attaches it as an image; it needs Screen Recording access, and without it a capsule beside the buttons offers Allow…, which resets Meraline's own entry with `tccutil` and asks, as Accessibility does. `ContextSources.addClipboard(to:)` and `addScreenshot(of:to:)` do the adding, and hold the capsule's notice, for the buttons and for `meraline://ask?clipboard=1&screen=1` (`PanelController.addContext`) alike; keep it one path. Nothing they add is saved anywhere; games take none of it, so the buttons fade out while one is on.
- **Show What Changed.** An answer that gives back the text its question was about, changed (“Fix the grammar” about a selection or the clipboard), offers Show What Changed under it and in the chat's actions (⌘D, the last answer's): the answer's place shows the text with what went struck through in red and what came in green, word by word, each on a faint tint of its color, and the button, one view whose label changes, says Show Answer to go back. Beside it either way, and on its row in the actions, the changes in numbers only (`TextChanges.stats`): “5% changed · 6 edits”, the letters and marks that went or came out of those in both texts, where a word put right counts only its letters that differ, so a typo is a small change; “<1%” when an edit rounds to nothing, and “0% changed” without edits. The strike tells the two apart for the colorblind; keep it. `ChatSession` looks for the changes off the main actor when an answer ends without being stopped (`findChanges(at:)`, then `Turn.changes`), against the texts of its question, or for a follow-up about none, of the last question that had some, and each of them together. `TextChanges.find` compares the whole answer, what follows a first line ending in a colon, and each code block (drawn in monospace) or quote, and keeps the part with the most of the text in order: at least `minimumSimilarity` (half) of its letters and marks, so explanations, summaries, and translations have none, and a short word put right still counts. Words, runs of spacing, and marks are compared by Myers's algorithm, inside the grid, up to `editLimit` of them going and coming; spacing swapped for spacing shows as the new spacing. Typed text in the question is never compared. Which answers show their changes is `PanelLayout.answersShowingChanges`, in memory only; Copy, Insert, and Tear Off always take the answer.
- **Prompts.** Settings › Prompt edits every system prompt Meraline sends (`SystemPrompt`): one for the LLMs, one for the agents (`ChatSession.makeRequest` picks by the provider's mode), each game's, and the one Why? runs with (`ToolReason`). The agents' gets `PresentFilesServer.instructions` added after it, which Settings doesn't show. Nor does it show what the follow-ups under an answer are asked with (`FollowUps.instructions(in:)`), which only Apple's on-device model reads. At the top of the pane, Language (`Preferences.language`, an `AnswerLanguage`, English by default, kept in UserDefaults) adds one line after whichever prompt a request sends (`Preferences.instructions(for:)`, never saved into the prompt): chats and agents answer in it unless asked for another language, and the games and Why?, written in English, get a line only for another language, telling a game to keep the markers it reads (“OK: ”, “ | ”, …) as they are. Each prompt's default lives in code (a game's `GameRules.systemPrompt`), and only a changed prompt is kept in UserDefaults, under `systemPrompt.<name>`, so one set back to its default follows later defaults. The one prompt of older versions (`systemPrompt`) carries over to both modes once, when it was changed. A game reads the model's replies in the format its prompt asks for, so its default and its parsing change together. Presets (`PromptPreset`: Fix Grammar, Anti-Slop, Anonymize, and Translate, into the Language, by default) are no system prompt but a first question of your own: glass capsules of an icon and a name above an empty chat's top right, lined up with the gear, in the room the buttons on the left leave (the names give way to the icons, then the row scrolls). A click puts the preset's text in the input ahead of what is typed, another preset's text giving way to it, and a second click takes it out, pink while it is there; a Shift-click sends it, and while Shift is down the capsule under the pointer shows an arrow. They are never in the chat's actions (⌘K), and once a chat starts they sink into the card one after another, staying in the view tree faded and disabled, so nothing is inserted while the window is hidden. Settings › Prompt edits, adds, moves, and deletes them, icons included (`PresetsSection`); only a changed list is kept, in UserDefaults under `promptPresets`, so presets left alone follow later defaults and the Language, and Copy Diagnostics says only whether they changed and how many there are.
- **Links in answers.** `AnswerLinks` turns a path in an answer into a link only when it names a file or folder on this Mac, and a `meraline://` URL only when it has a route. A path counts when it is absolute, starts with `~/`, or, in an agent's chat, is relative to its workspace (`answerWorkspace` in the environment) and has a slash or an extension. It may take in up to `wordsWithSpaces` more words, or a whole code span, for names with spaces, and a line number after it (`App.swift:42`) stays in the link. A link the model wrote to a path leads to the file too. Code blocks are left alone. Links are found each time an answer is drawn, on the main thread, and kept nowhere, so paths on servers and autofs (`remoteMountPoints()`) are never looked at: a look there can wait a minute. A click opens by a handed-over file's rules (`PresentedFile.opening(of:isFolder:)`: nothing runs, scripts open as text, apps are only shown in Finder), marking a workspace file as downloaded first; ⌘-click, read off the click itself, shows it in Finder. A `meraline://` link runs its route in this Meraline without its `send` (`AutomationRoute.withoutSending`), so a question the model wrote waits for Return. A torn-off note keeps its chat's workspace for them.
- **Privacy signals.** The panel doesn't label providers that answer on this Mac; the "on this Mac" badge was removed on purpose, so don't bring it back. Hide from Screen Sharing (`Preferences.hidesFromScreenSharing`, off by default, in Settings › General › Privacy and the sparkle's panel, shown as a crossed-out eye beside the mode toggle) sets the panel's `sharingType` to `.none`. Since macOS 15, captures of the whole display through ScreenCaptureKit (QuickTime, OBS, some video-call apps) show the window anyway, so copy never promises it is invisible. Settings › General › Privacy can also forget every chat when the Mac or its display goes to sleep (`Preferences.forgetsChatsOnSleep`) and when the screen locks or another user takes the screen (`forgetsChatsOnLock`), both off by default. `AwayWatcher`, which `AppDelegate` keeps, hears NSWorkspace's sleep and session notifications and the distributed `com.apple.screenIsLocked`, and `PanelController.forgetChats()` forgets as quitting does (`ChatSession.forgetAll()`): the open chat with what is typed and offered for it, Recent Chats, their workspaces and live agents, torn-off answers, and any panel of actions. The window stays as it was, and so does the games' tally, which holds no word of a chat. Shutting down, restarting, and logging out quit Meraline, which forgets everything anyway, so they need no setting.
- **Agents and MCP.** Settings groups providers as LLMs (the services) and Agents (Claude Code, Codex, OpenCode). Agents may use the MCP servers set up in them. Meraline lists those by asking the agent (`<agent> mcp list`), never edits an agent's configuration, and keeps only server names in UserDefaults (they are settings, not chat content). A run names its servers one by one, because claude's allow rules need a server name and `mcp__*` does nothing, and turns off the ones off in Settings through the agent's own overrides (`--disallowedTools mcp__<server>`, `-c mcp_servers.<name>.enabled=false`, `OPENCODE_CONFIG_CONTENT`). What an agent is asking shows while it answers, and the tools an answer used sit under it. Once the answer is finished, a click on a tool's capsule (`ToolTrail`) has the provider that answered say in one line under them why it used that tool (`ToolReason.explain(toolAt:of:in:provider:settings:instructions:stream:)`), from the chat up to that answer, the answer, and the capsules' own words, since the trail keeps no tool's input: Claude Code in Why?'s short run, any other provider in a request of its own with its settings less the web and MCP servers and no workspace. It is never another provider, so the chat goes nowhere it didn't go already, and a turn whose provider isn't ready any more offers none. The one Why? prompt serves both, and a reason is kept only by the trail's view state. An agent works in the chat's workspace: Claude Code has its file tools, Bash, and its skills there and asks over stdin and stdout (`--permission-prompt-tool stdio`, `control_request` in, `control_response` out) before a write, a command it doesn't judge read-only, or a skill, or when it has a question (`AskUserQuestion`), which the panel shows as a card with Allow and Deny (and Why?, which asks Claude Code for its reason in one line in a short run of its own: `ToolReason`, haiku, no tools, no MCP servers, no thinking) or the question's choices; Codex runs as `codex app-server` in ephemeral threads with a `workspace-write` sandbox and approvals off, so it cannot ask; OpenCode's run mode turns its own asks down, which the panel reports. Each ask and how it was settled stays with the turn (`Turn.prompts`). Claude Code's stdin stays open until its `result`, never just a `message_stop`: every message ends in one, the one that calls a tool too, and closing stdin then turns down the ask still waiting. Claude Code and Codex stay running for their chat (`LiveAgents`, keyed by the workspace, at most `LiveAgents.limit`, ended after `idleLifetime` unused, by Stop, or with the workspace) and start ahead when the window opens in Agent mode (`ChatSession.prewarm()`): a follow-up sends only the new question, and anything else, Ask Again, a rewrite, another provider's answer in between, starts over from the transcript, in a new process or a new Codex thread. Nothing is resumed from disk. Every chat with an agent (not a game) also gets Meraline's own MCP server (`PresentFilesServer`), whatever Settings says about the others, and a paragraph of the system prompt on when to use its one tool, `present_files`, which hands files to the person. The server is Meraline's own executable started with `--present-files-server <workspace>` (`MeralineApp.main` checks for it before anything else starts), so there is no helper to sign; it goes in through `--mcp-config` and `--allowedTools`, `-c mcp_servers.meraline.*` after the overrides that turn servers off, and `OPENCODE_CONFIG_CONTENT`. It only checks the paths, inside the workspace with symlinks resolved (`PresentedFile.handOver`), and answers; the panel reads the same call from the agent's stream (`StreamChunk.presented`) and checks it the same way, so it shows exactly what the agent was told it handed over. The files show as cards under the answer (`Turn.presentedFiles`) with Open in the app the Mac opens them with, Show in Finder, Copy, Save to Downloads, and dragging out, and the chat's actions offer the same for the last ones (⌘O, ⌘S). A picture shows itself on its card instead of its icon (`PresentedFile.picture(at:)`: read off the main thread, at most 1,200 px on its longer side, kept only in the card), up to `PresentedFileCard.pictureHeight` and never above its own pixels; a click shows it larger, up to `enlargedPictureHeight`, inside the window. Not Quick Look: its window would take the keyboard and close the panel. A page (HTML) or a Markdown file shows a glass preview strip there instead (`FilePreviewStrip`), up to `FilePreviewStrip.height`, fading out where the file goes on; a click shows more, up to `enlargedHeight`. Markdown's first lines (`FilePreview.markdown(at:)`: at most 16 KB and 200 lines, front matter left out) are drawn by `MarkdownView`. A page is drawn by an `InertWebView`, which no click, key, scroll, or pointer reaches, and loads only once scrolled into view: the page's scripts off (`allowsContentJavaScript`; only Meraline's own script runs, to measure it and hide its scroll bars), a content rule list that blocks every load but `file:`, `data:`, and `about:` (compiled once into WebKit's store, which holds only the rules), read access to the workspace alone, no navigation past its own file, a non-persistent data store, and no media playing by itself. Keep it so: an agent's page can come from anywhere, and looking at it must never tell a server. A file is marked as downloaded (quarantined) before it leaves for another app, and Open never runs anything: scripts open in the plain-text app, and apps, programs, and files that run or install something (`.terminal`, `.mobileconfig`, …) are only shown in Finder.
- **Releases.** Version comes from the tag (a suffix, as in `v1.8.0-beta.1`, makes a beta, and `UpdateChannel(version:)` reads the running version the same way for Settings' chip), the build number is the commit count, and a release is always signed and notarized. The release's `CHANGELOG.md` section shows its new features with screenshots from `docs/screenshots`, linked at the tag (see docs/releasing.md). Take a picture with `scripts/showcase.sh` whenever its state can be scripted: add a scene to `ShowcaseTests` with a `ScriptedModel`, seeded dice, or `DemoUsage`. It never clicks or types and runs while someone works, only taking the keyboard for about a second per picture after 5 s without input, because a window draws its active look (pink glass tints, the text cursor, colored traffic lights) only while it has the keyboard. Its pictures match `scripts/screenshots.sh`'s: the same gradient, sizes, and file names. Keep that script for what needs a real provider, an agent, or clicks, and never drive the UI while the Mac is in use. A plain offscreen render (`cacheDisplay`) draws no glass, so it only checks layout. Never re-introduce `codesign --deep`. The layout numbers in `assets/dmg/background.html` and `scripts/lib/dmg.sh` must change together.
