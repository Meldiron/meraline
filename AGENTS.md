# AGENTS.md

Meraline is a macOS 26 menu bar app for quick, ephemeral AI chats: press ⌥ Space, ask, read the streamed answer, let it go. Swift 6, SwiftUI plus AppKit, no sandbox, hardened runtime. This file is the entry point for agents and contributors; [CONTRIBUTING.md](CONTRIBUTING.md) is the human-facing version.

## Build, test, run

The Xcode project is **generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)** from `project.yml` and is gitignored. Re-run `xcodegen generate` after adding or removing files; every script does it for you.

```sh
scripts/dev_run.sh                  # Debug build, relaunch from DerivedData, logs in /tmp/meraline.log
scripts/test.sh                     # full test suite (Swift Testing), xcbeautify output when installed
scripts/test.sh HistoryTests        # one test struct
scripts/test.sh --e2e               # also run the installed claude, codex, and opencode for real
scripts/install.sh                  # clean Release build into /Applications and launch it
scripts/clean.sh                    # remove build/ and DerivedData
scripts/screenshots.sh --wait-idle  # README screenshots of every feature, dark and light, once the Mac is idle
scripts/release.sh 1.2.0 --adhoc    # the whole release pipeline without credentials (see docs/releasing.md)
```

Dependencies are pinned to exact versions in `project.yml` (Sparkle, KeyboardShortcuts, EventSource). Bump them there, deliberately.

A Developer ID certificate is optional. `dev_run.sh`, `test.sh`, and `release.sh --adhoc` sign ad-hoc when the certificate is missing; only `install.sh` and real releases need it. When it is there, don't force ad-hoc signing (`CODE_SIGN_IDENTITY=-`): macOS treats every ad-hoc build as a new app, so a build that runs asks for the Keychain password and loses Accessibility access each time. The test host never starts the app (`MeralineApp.isHostingTests`), so tests don't read the Keychain or take the shortcut, however they are signed.

## Commits

Commit as you go. Every change that is done and passes its tests gets its own commit right away, so the history reads as a list of what changed, one step at a time. Don't leave finished work uncommitted at the end of a session, and don't save a day of work for one big commit.

- **One change per commit.** A feature, a fix, a refactor, a batch of screenshots, or a docs pass is each its own commit. The code, its tests, the docs it changes (README, AGENTS.md, `docs/`), and its bullet under `## Unreleased` in CHANGELOG.md go in together. Every commit builds and passes `scripts/test.sh`.
- **Say what changed, in plain words.** The subject is one line, in sentence case with no prefix and no final period, that says what the change does for someone using Meraline or working on it, the way the changelog would: "Agents hand files over with present_files", "Fix the window not moving on macOS 27". Keep it under about 70 characters. When the reason isn't obvious from the subject, add a body after a blank line.
- **Commit only your own work.** Several sessions often edit this checkout at once. Stage what you changed by path (`git add <path>`; never `git add -A`, `git add .`, or `git commit -a`) and read `git diff --cached` before you commit. When a file you changed also holds another session's unfinished edits, stage only your hunks (save `git diff <path>` to a patch, cut it down to yours, and `git apply --cached` it), or wait until theirs are committed.
- **Commit on `main`, push when asked.** Never amend, rebase, or force-push a commit that has been pushed or that another session made.
- **Never commit** `SESSION_NOTES.md`, `research_notes/`, or `reports/` (they are in `.git/info/exclude`), `build/`, or the generated `Meraline.xcodeproj`.

## Hard rules

- **Nothing on disk.** Conversations, drafts, images, and recent chats stay in memory. Do not add persistence for them. The one folder an agent gets is the chat's workspace (`ChatWorkspace`, an empty temporary folder per chat): it holds only the files and folders you attach and what the agent writes there, and goes with the chat (when its time runs out, it is deleted, or it leaves Recent Chats, not on Esc) or at quit. At most `ChatSession.chatLimit` (1,000) chats are in memory, the open one included, so Recent Chats drops its oldest, workspace and all, past 999; a chat takes at most `ChatSession.chatByteLimit` (512 MB, pictures mostly), and a question past it stays in the input; a workspace takes in at most `FileAttachment.folderLimit` (20,000) files and folders from attachments, counting what is there already. macOS clears old files out of the temporary folder: a workspace found missing is made again, empty, its live agent ends, and the next question carries a warning (`Turn.notice`). An attachment is copied in when its question is sent; until then the draft keeps only its path. A file the agent hands over stays in the workspace; only Save to Downloads, which you click, writes anywhere else.
- **Secrets go through `SecretStore`.** API keys are Keychain items; never put them in UserDefaults, logs, diagnostics, or URLs.
- **Log through `Log`, never `print`.** `Log.<category>.info(...)` writes to `os.Logger` and the in-memory buffer that feeds the diagnostics report. Log providers, models, paths, and error descriptions; never questions, answers, or keys.
- **Swift 6, strict concurrency, `MainActor` by default.** Networking and parsing types are `nonisolated`. Sparkle's KVO and delegate callbacks must read their arguments rather than main-actor state.
- **Design.** The base is neutral glass: white, black, gray, graphite accent. Pink appears only as an accent (text cursor, the sparkle in the input row, toggles, the active pin, a faint glass tint on buttons). Never solid pink buttons or strong pink backgrounds. Never rotate a view that has glass on it: glass in the panel's container swells into a disc beside its place while it turns. Rotate the symbol inside instead (scaling glass is fine). The logo is the sparkle character with a face; do not change it. The panel draws its own rounded shadow and keeps the window shadow off. Its SwiftUI content is laid out at a fixed height, pinned to the window's top (`PanelController.sizeContent()`), and the window only shows as much as the card needs: it grows at once and shrinks after the card's animation. Don't make the hosting view the window's content view again; a window resize would then resize the layout mid-animation and drop the card by half its growth.
- **Behavior.** Return or Tab sends. Esc puts away the shortcut picker, closes a panel of actions (or backs out of its confirmation), folds away the What's New notes, stops, then starts a new chat, then closes. Closing the window only hides it. Every chat has its own time, `ChatSession.chatLifetime` (30 minutes, no setting): a message, the end of an answer, reopening the chat, or a click on its timer starts it over. It keeps running in Recent Chats. When it runs out, the chat goes with its workspace without passing through Recent Chats; what is typed in the input stays, and an answer still coming holds the open chat until it ends. `ChatSession.expireChats(now:)` does it, at each deadline and when the window opens, in case the Mac slept through one. The timer (`ChatTimer`) is a neutral glass capsule under the card's bottom right, lined up with the footer's actions, in the same bottom margin as the capsules on the left: minutes left, then seconds in the last one. The pin has no countdown, and Settings › General › Start a new chat was removed on purpose; don't bring them back. Capsules under the card's bottom left, lined up with the buttons above its top left (`Announcements`, drawn in the window's bottom margin, which is `Announcements.roomBelow` taller while one shows), announce updates and a crash. After Meraline quits unexpectedly, the next launch finds macOS's report of it in ~/Library/Logs/DiagnosticReports (or its Retired folder), newer than the launch before (`CrashNotice`, which keeps only the launch date in UserDefaults), and a Copy Diagnostics capsule copies the report with a Crash section, says Copied, and goes; its cross hides it too, and the next launch never offers the same crash again. The section keeps only the exception, the termination, the Swift runtime's words up to their first colon (none if they quote something) or an uncaught exception's name (never its reason), Meraline's image UUID and load address, and the crashed thread's frames, so the diagnostics still hold no question, answer, or key; Settings › About › Copy Diagnostics includes it for the rest of that run. After an update, What's New opens the notes under the input, with their screenshots (`ReleaseNotes.Block.picture`, fetched when the notes open through an ephemeral session and kept in memory), until its cross or Got It hides it; `WhatsNew` keeps the version and Sparkle's notes in UserDefaults so the next update brings it back, and there is no What's new window. Beside it, an update Sparkle found (Update Available, which opens Sparkle's window) or staged (Restart to Update) shows until its cross hides that version; `UpdateNotice` keeps the hidden version in UserDefaults, so only a newer update brings it back. The menu bar item and Settings › Software Update offer the update regardless. On the first launch the window opens on a shortcut picker (`ShortcutSetup`, until `hasChosenShortcut` is set) before the shortcut is ever pressed: it checks whether macOS uses ⌥ Space, whether Meraline could register it, and whether ChatGPT, Gemini, Copilot, Raycast, Alfred, SpotAsk, or Seer is running or installed, then offers Keep or suggestions that skip whatever looks taken. A suggestion is registered under `shortcutTrial` until it is pressed, which keeps it, or Use This Shortcut. Esc or a click elsewhere keeps ⌥ Space and leaves a capsule under the empty input that opens Settings › General on the recorder, until the shortcut changes or its cross hides it. The row under the input (`ModeBar`) holds the LLM and Agent toggle on the left (⌘1, ⌘2) with the privacy badges beside it and, on the right, the games behind a controller and Recent Chats behind a clock that shows their count. The controller opens and closes the games; one tray is open at a time, and `PanelLayout` remembers which while the window is hidden, in memory only. `GameTray` lays out every frame of its spring from one animated `openness` (the capsule's width, how much of the row shows, each game's fade), so nothing is inserted or removed while it moves; keep it that way, since inserted views land ahead of the glass. The footer under a chat shows one primary action (Stop, Copy Answer, or a game's Hint or End Game) and Actions ⌘K; the rest live in a panel of actions, as do the sparkle's providers and the clock's recent chats. Beside Ask Again, the chat's panel rewrites the last answer (`ChatSession.rewrite(_:)`: shorter, longer, simpler, more concrete, a bullet list): the provider in use gets the conversation and the rewrite's instruction, and the new answer takes the old one's place under the same question, so follow-ups and the next rewrite read it; the instruction never shows. A rewrite stopped or failed partway puts the old answer back. The three panels are one component (`ActionPanel`) drawn inside the window over the card, with a search field, arrows and Return, and keycaps. The chat's and the clock's open up and to the left of their buttons; past the card's top, the window raises its own top (`PanelController.fit(height:roomAbove:)`) so the card never moves on the screen, and only when the screen has no room above do they open downward. The sparkle's opens down and to the right. An action that can't be undone (Delete Chat ⇧⌘⌫, Clear Recent Chats) confirms inside the panel, never with an alert or sheet, because the window closes when it loses the keyboard. Insert Answer (⌘↵, `AnswerInserter`; the shortcut steps aside while the input has text) closes the window, which hands the keyboard back to the app in front since the panel never activates Meraline, and pastes the last answer at its cursor through that app's Paste menu item, or ⌘V when it has none that reads enabled; the answer sits on the clipboard marked `org.nspasteboard.TransientType` and the clipboard is put back after, unless something else was copied meanwhile. Without Accessibility access it only copies. It is not offered when Meraline itself is in front. Tear Off Answer (⌘T) opens the last answer in a floating glass note (`AnswerNotes`, in memory only), beside the window: it moves by its header or empty space, resizes from its sides and bottom (it fits its answer until then), folds its question away, and draws its shadow as a layer of its own behind the glass, since a shadow on glass shows only while its window is key. Borderless windows move through `WindowDragArea` behind their content, not `isMovableByWindowBackground`, which stopped moving them once SwiftUI took the click. The chat's shortcuts (⇧⌘C, ⌥⇧⌘C, ⌘↵, ⌘T, ⌘R Ask Again, ⌘N, ⇧⌘O, ⇧⌘⌫, and a game's ⌘I and ⌘R) are matched by `PanelController`'s key monitor against `PanelContext.chatMenu`, so they work with or without a panel open. Shaking the window while dragging it (`ShakeDetector`, fed by `windowDidMove`) forgets the recent chats like Clear Recent Chats, without asking, and the clock's capsule says so for a moment; the panel does not mention the shake. Each mode keeps its own provider (`Preferences.mode`, `defaultProvider(for:)`), and the sparkle's panel lists only the ready providers of the current mode; there is no model switcher in the panel, and Recent Chats are not in the sparkle's panel. The sparkle's panel also turns anonymous mode on and off, as does ⇧⌘N (`ChatSession.isAnonymous`, in memory only and never saved): whatever chat is open when it ends skips Recent Chats and its workspace goes with it, the sparkle goes graphite with sunglasses cut out of it (`SparkleIcon`, drawn from the app icon's sparkle), and the input asks "Ask anything secretly…". Games are a mode of `ChatSession`, started from their buttons in that row, and the model always moves first. A game's rules work everything out from the turns, so a game keeps no state of its own; answers the model hides after a `|` in its reply stay hidden until you have played, except that Hint in the footer shows a game's hints for your move one at a time (Rhyme Duel's are the rhymes the model hid for its last word; Letter Auction's, the words the banker's deal makes). Each game sends its own system prompt instead of the LLMs' or the agents', lives only in memory like any chat, and Esc or End Game ends it. A move that breaks the rules comes back to the input and costs nothing. A round that ends says who won it (`.over(outcome:rematch:)`), and `ChatSession.versus` counts each game's rounds against the model; the rematch tray (`RematchTray`) shows that tally with Play Again (⌘R) under the transcript once a round is over, and stays on the empty panel after the game until a new game or its cross. The tally and the tray are the one game state that outlives a chat, and they live in memory only, so quitting forgets them.
- **Attachments.** Dropping or pasting (⌘V) attaches an image, which works in either mode, or any other file or a folder, which only an agent reads: the prompt names it and the agent finds a copy in its working directory, a subfolder for a folder. The agent starts one level above a copied project on purpose, so the project's own agent settings (hooks, `opencode.json`, `.mcp.json`) never load by themselves. A folder in git brings what `git ls-files --cached --others --exclude-standard` lists, plus `.git` at a repository's top; any other folder comes whole; either way at most `FileAttachment.folderLimit` files, and never a disk or the home folder. In LLM mode an attachment waits in the draft under a row with Switch to Agent, and Return does nothing until you switch or remove it. Games take neither.
- **Selected text and files.** The shortcut reads the frontmost app's selection before the panel takes the keyboard (`PanelController.toggleBringingSelection`): through Accessibility first (selected text, or else the selected items of a file browser, whose `AXURL` names the file, as Finder's do), and for an app that doesn't answer, by pressing the ⌘C item in its own menu through Accessibility and restoring the clipboard. Only an app whose focused element is its window, so it describes none of its content (Zed), gets a posted ⌘C, with the key that types C in the current layout and only when its menu item is missing or reads disabled; other apps never get a keystroke, so nothing beeps. A copy that VS Code (`isFromEmptySelection`, inside Chromium's `org.chromium.web-custom-data`) or Zed (`is_entire_line` in `zed-metadata`) marks as a line copied from an empty selection counts as nothing selected. It never reads Meraline, password fields, or under secure input. Selected text never joins the question by itself: the shortcut only offers it (`ChatSession.offeredSelection`, withdrawn when the window closes), and the selection button above the card adds it to the draft (`toggleOfferedSelection()`). The button can't read the selection itself, because by the time it is clicked the panel has the keyboard. Once added, each text waits in the draft (`draftSelections`, as many as you add) in a card of its own between the input and the `ModeBar`, goes with the question as a `<selected_text from="App">` block, in order, and stays with the turn as a quote (`Turn.selections`). The Services menu (`NSServices` in project.yml) and `meraline://ask?selection=` bring it without Accessibility access. Finder files go through `ChatSession.bring(files:)`: photos in either mode, anything else, folders included, only in Agent mode (the Services menu brings everything, like a drop), and each press of the shortcut takes exactly what is selected then (`bringCurrentSelection`): files replace what an earlier selection brought and text replaces the offer, and nothing selected takes both away, while anything added by hand, the draft's text included, stays. ⌫ in an empty input takes out the last text, then the last attachment, and ignores key repeats. Games ignore both. Only the on/off setting and whether the hint was dismissed live in UserDefaults.
- **Selection, clipboard, and screenshot.** Three glass circles float above the card's top left, lined up with the sparkle (`ContextButtons`, drawn in the window's top margin, which is `ContextButtons.roomAbove` taller for them). Context adds up: every click adds what its button has now, so texts from several apps, several copies, and a screenshot per visit can all go with one question. A click takes out instead only when that exact version is in the draft already: the same selected text (`SelectedText.isSame(as:)`), the same clipboard copy (by `NSPasteboard.changeCount`), or the same visit to the screen (`ContextSources.screenVisit`, which moves when the window opens, the app in front changes, or the window changes screens). `ContextSources` (owned by `PanelController`, in memory) remembers which draft items came from which copy or visit; ⌘V's attachments count as the clipboard's. Each button has three states (`ContextButtons.Status`): unavailable, faded and disabled (no text offered, nothing addable on the clipboard, or the draft at `ImageAttachment.limit` images); available, neutral glass; and added, the active pin's pink symbol and faint pink glass. Don't collapse them. The selection button (⇧⌘E, a text cursor at the end of a highlight, drawn by hand in `SelectionIcon`) toggles the offered text (`toggleOfferedSelection()`). The clipboard (⇧⌘V) reads `NSPasteboard.general` through `ClipboardContent`: copied files attach as ⌘V attaches them, a picture as an image, and text goes to a card of its own as `SelectedText.clipboard` (`isFromClipboard`), which the model reads as a `<clipboard>` block; with both a picture and text, the kind the copying app listed first wins. While the window is up, `ContextSources` looks at the change count every 0.75 s, and at the clipboard's kinds (never its contents) when it moves; anything a password manager marks `org.nspasteboard.ConcealedType` or `TransientType` is never read. The screen (⇧⌘S) takes one picture of the screen the window is on with ScreenCaptureKit, leaving out every Meraline window (`SCContentFilter` excluding Meraline's own app), and attaches it as an image; it needs Screen Recording access, and without it a capsule beside the buttons offers Allow…, which resets Meraline's own entry with `tccutil` and asks, as Accessibility does. `ContextSources.addClipboard(to:)` and `addScreenshot(of:to:)` do the adding, and hold the capsule's notice, for the buttons and for `meraline://ask?clipboard=1&screen=1` (`PanelController.addContext`) alike; keep it one path. Nothing they add is saved anywhere; games take none of it, so the buttons fade out while one is on.
- **Prompts.** Settings › Prompt edits every system prompt Meraline sends (`SystemPrompt`): one for the LLMs, one for the agents (`ChatSession.makeRequest` picks by the provider's mode), each game's, and the one Why? runs with (`ToolReason`). The agents' gets `PresentFilesServer.instructions` added after it, which Settings doesn't show. Each prompt's default lives in code (a game's `GameRules.systemPrompt`), and only a changed prompt is kept in UserDefaults, under `systemPrompt.<name>`, so one set back to its default follows later defaults. The one prompt of older versions (`systemPrompt`) carries over to both modes once, when it was changed. A game reads the model's replies in the format its prompt asks for, so its default and its parsing change together.
- **Privacy signals.** The panel doesn't label providers that answer on this Mac; the "on this Mac" badge was removed on purpose, so don't bring it back. Hide from Screen Sharing (`Preferences.hidesFromScreenSharing`, off by default, in Settings › General › Privacy and the sparkle's panel, shown as a crossed-out eye beside the mode toggle) sets the panel's `sharingType` to `.none`. Since macOS 15, captures of the whole display through ScreenCaptureKit (QuickTime, OBS, some video-call apps) show the window anyway, so copy never promises it is invisible.
- **Agents and MCP.** Settings groups providers as LLMs (the services) and Agents (Claude Code, Codex, OpenCode). Agents may use the MCP servers set up in them. Meraline lists those by asking the agent (`<agent> mcp list`), never edits an agent's configuration, and keeps only server names in UserDefaults (they are settings, not chat content). A run names its servers one by one, because claude's allow rules need a server name and `mcp__*` does nothing, and turns off the ones off in Settings through the agent's own overrides (`--disallowedTools mcp__<server>`, `-c mcp_servers.<name>.enabled=false`, `OPENCODE_CONFIG_CONTENT`). What an agent is asking shows while it answers, and the tools an answer used sit under it. An agent works in the chat's workspace: Claude Code has its file tools, Bash, and its skills there and asks over stdin and stdout (`--permission-prompt-tool stdio`, `control_request` in, `control_response` out) before a write, a command it doesn't judge read-only, or a skill, or when it has a question (`AskUserQuestion`), which the panel shows as a card with Allow and Deny (and Why?, which asks Claude Code for its reason in one line in a short run of its own: `ToolReason`, haiku, no tools, no MCP servers, no thinking) or the question's choices; Codex runs as `codex app-server` in ephemeral threads with a `workspace-write` sandbox and approvals off, so it cannot ask; OpenCode's run mode turns its own asks down, which the panel reports. Each ask and how it was settled stays with the turn (`Turn.prompts`). Claude Code's stdin stays open until its `result`, never just a `message_stop`: every message ends in one, the one that calls a tool too, and closing stdin then turns down the ask still waiting. Claude Code and Codex stay running for their chat (`LiveAgents`, keyed by the workspace, at most `LiveAgents.limit`, ended after `idleLifetime` unused, by Stop, or with the workspace) and start ahead when the window opens in Agent mode (`ChatSession.prewarm()`): a follow-up sends only the new question, and anything else, Ask Again, a rewrite, another provider's answer in between, starts over from the transcript, in a new process or a new Codex thread. Nothing is resumed from disk. Every chat with an agent (not a game) also gets Meraline's own MCP server (`PresentFilesServer`), whatever Settings says about the others, and a paragraph of the system prompt on when to use its one tool, `present_files`, which hands files to the person. The server is Meraline's own executable started with `--present-files-server <workspace>` (`MeralineApp.main` checks for it before anything else starts), so there is no helper to sign; it goes in through `--mcp-config` and `--allowedTools`, `-c mcp_servers.meraline.*` after the overrides that turn servers off, and `OPENCODE_CONFIG_CONTENT`. It only checks the paths, inside the workspace with symlinks resolved (`PresentedFile.handOver`), and answers; the panel reads the same call from the agent's stream (`StreamChunk.presented`) and checks it the same way, so it shows exactly what the agent was told it handed over. The files show as cards under the answer (`Turn.presentedFiles`) with Open in the app the Mac opens them with, Show in Finder, Copy, Save to Downloads, and dragging out, and the chat's actions offer the same for the last ones (⌘O, ⌘S). A picture shows itself on its card instead of its icon (`PresentedFile.picture(at:)`: read off the main thread, at most 1,200 px on its longer side, kept only in the card), up to `PresentedFileCard.pictureHeight` and never above its own pixels; a click shows it larger, up to `enlargedPictureHeight`, inside the window. Not Quick Look: its window would take the keyboard and close the panel. A file is marked as downloaded (quarantined) before it leaves for another app, and Open never runs anything: scripts open in the plain-text app, and apps, programs, and files that run or install something (`.terminal`, `.mobileconfig`, …) are only shown in Finder.
- **Releases.** Version comes from the tag, the build number is the commit count, and a release is always signed and notarized. The release's `CHANGELOG.md` section shows its new features with screenshots from `docs/screenshots`, linked at the tag (see docs/releasing.md). Never re-introduce `codesign --deep`. The layout numbers in `assets/dmg/background.html` and `scripts/lib/dmg.sh` must change together.
