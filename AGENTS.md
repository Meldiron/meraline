# AGENTS.md

Meraline is a macOS 26 menu bar app for quick, ephemeral AI chats: press ⌥ Space, ask, read the streamed answer, let it go. Swift 6, SwiftUI plus AppKit, no sandbox, hardened runtime. This file is the entry point for agents and contributors; [CONTRIBUTING.md](CONTRIBUTING.md) is the human-facing version.

## Build, test, run

The Xcode project is **generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)** from `project.yml` and is gitignored. Re-run `xcodegen generate` after adding or removing files; every script does it for you.

```sh
scripts/dev_run.sh                  # Debug build, relaunch from DerivedData, logs in /tmp/meraline.log
scripts/test.sh                     # full test suite (Swift Testing), xcbeautify output when installed
scripts/test.sh HistoryTests        # one test struct
scripts/test.sh --e2e               # also run the installed claude, codex, and opencode for real
scripts/install.sh                  # clean Release build into /Applications and launch it
scripts/clean.sh                    # remove build/ and DerivedData
scripts/showcase.sh                 # pictures of scripted scenes (games, Settings panes), dark and light, while you work
scripts/clips.sh --out build/clips  # clips of the panel's animations (opening, asking, Show What Changed), to judge a change against the version before
scripts/screenshots.sh --wait-idle  # README screenshots that need a real provider, an agent, or clicks, once the Mac is idle
scripts/release.sh 1.2.0 --adhoc    # the whole release pipeline without credentials (see docs/releasing.md)
```

Dependencies are pinned to exact versions in `project.yml` (Sparkle, KeyboardShortcuts, EventSource). Bump them there, deliberately.

A Developer ID certificate is optional. `dev_run.sh`, `test.sh`, and `release.sh --adhoc` sign ad-hoc when the certificate is missing; only `install.sh` and real releases need it. When it is there, don't force ad-hoc signing (`CODE_SIGN_IDENTITY=-`): macOS treats every ad-hoc build as a new app, so a build that runs asks for the Keychain password and loses Accessibility access each time. The test host never starts the app (`MeralineApp.isHostingTests`), so tests don't read the Keychain or take the shortcut, however they are signed.

## Commits

Commit as you go. Every change that is done and passes its tests gets its own commit right away, so the history reads as a list of what changed, one step at a time. Don't leave finished work uncommitted at the end of a session, and don't save a day of work for one big commit.

- **One change per commit.** A feature, a fix, a refactor, a batch of screenshots, or a docs pass is each its own commit. The code, its tests, the docs it changes (README, AGENTS.md, `docs/`), and its bullet under `## Unreleased` in CHANGELOG.md go in together. Every commit builds and passes `scripts/test.sh`.
- **Say what changed, in plain words.** The subject is one line, in sentence case with no prefix and no final period, that says what the change does for someone using Meraline or working on it, the way the changelog would: "Agents hand files over with present_files", "Fix the window not moving on macOS 27". Keep it under about 70 characters. When the reason isn't obvious from the subject, add a body after a blank line.
- **Commit only your own work.** Several sessions often edit this checkout at once. Stage what you changed by path (`git add <path>`; never `git add -A`, `git add .`, or `git commit -a`) and read `git diff --cached` before you commit. When a file you changed also holds another session's unfinished edits, stage only your hunks (save `git diff <path>` to a patch, cut it down to yours, and `git apply --cached` it), or wait until theirs are committed.
- **Commit on `main`, push when asked.** Never amend, rebase, or force-push a commit that has been pushed or that another session made.
- **Never commit** `SESSION_NOTES.md`, `research_notes/`, or `reports/` (they are in `.git/info/exclude`), `build/`, or the generated `Meraline.xcodeproj`.

## Hard rules

- **Nothing on disk.** Conversations, drafts, images, and recent chats stay in memory. Do not add persistence for them. The one folder an agent gets is the chat's workspace (`ChatWorkspace`, an empty temporary folder per chat): it holds only the files and folders you attach and what the agent writes there, and goes with the chat (when its time runs out, it is deleted, or it leaves Recent Chats, not on Esc) or at quit. At most `ChatSession.chatLimit` (1,000) chats are in memory, the open one included, so Recent Chats drops its oldest, workspace and all, past 999; a chat takes at most `ChatSession.chatByteLimit` (512 MB, pictures mostly), and a question past it stays in the input; a workspace takes in at most `FileAttachment.folderLimit` (20,000) files and folders from attachments, counting what is there already. macOS clears old files out of the temporary folder: a workspace found missing is made again, empty, its live agent ends, and the next question carries a warning (`Turn.notice`). An attachment is copied in when its question is sent; until then the draft keeps only its path. A file the agent hands over stays in the workspace; only Save to Downloads, which you click, writes anywhere else. The one other thing kept on disk is the usage ledger (`UsageLedger`, `~/Library/Application Support/Meraline/usage.json`): counts by five-minute slot of questions, answers, tokens and cost by model, games, their rounds and runs of wins, and each game's own numbers (`GameFigures`: scores, words' lengths, puzzles solved), agents' tools and asks, decisions and those under the Not Sure line, and what was done with answers, each slot's apart by the kind of model they came from (`UsageLedger.record(at:as:_:)`; a count recorded without a kind, and every slot of a file written before kinds, version 1, is parted by what it holds, `UsageTally.byKind()`), so Settings can show usage by the hour, day, week, month, and year, for the LLMs, the agents, the decision models, or any of them together. It holds no question, answer, title, model reply, or file name, only numbers and the names of providers, models, games, games' numbers (`GameStat`), and rewrites; `ChatSession` counts through its `usage` (`UsageLedger.shared` in the app, one in memory in tests), a token count the provider reports (`Turn.usage`) or else an estimate from length, and anonymous chats count like any other. Never put text into it.
- **Secrets go through `SecretStore`.** API keys are Keychain items; never put them in UserDefaults, logs, diagnostics, or URLs.
- **Log through `Log`, never `print`.** `Log.<category>.info(...)` writes to `os.Logger` and the in-memory buffer that feeds the diagnostics report. Log providers, models, paths, and error descriptions; never questions, answers, or keys.
- **Swift 6, strict concurrency, `MainActor` by default.** Networking and parsing types are `nonisolated`. Sparkle's KVO and delegate callbacks must read their arguments rather than main-actor state.
- **Design.** The base is neutral glass: white, black, gray, graphite accent. Pink appears only as an accent (text cursor, the sparkle in the input row, toggles, the active pin, a faint glass tint on buttons). Never solid pink buttons or strong pink backgrounds. Never rotate a view that has glass on it: glass in the panel's container swells into a disc beside its place while it turns. Rotate the symbol inside instead (scaling glass is fine). A fade or a scale on one glass view among others in a shared `GlassEffectContainer` never reaches its glass, since the container draws it: fade a view with glass through a container of its own (`PromptPresets` gives each capsule one, `ContextButtons` fades its whole row). The logo is the sparkle character with a face; do not change it. The panel draws its own rounded shadow and keeps the window shadow off, and the window keeps room for every shadow it draws to fade out: `PanelController.marginBelow` under the card (more than `margin` at its sides, since the card's shadow is offset downward), `ContextButtons.shadowRoom` under the capsules below the card and at the gear's end of the presets' row, and `ActionPanelHost.inset` and `insetBelow` above and below a panel of actions; a shadow that reached the window's edge ended in a hard line there. How clear or opaque the glass is follows macOS 27's Liquid Glass slider (System Settings › Appearance), which the system applies to every `glassEffect`; the SDK has no intensity API (`Glass` has only `.regular`, `.clear`, `.tint`, and `.interactive`) and no readable preference for the slider, and a glass slider of Meraline's own was decided against on 2026-10-02, so don't add one. Its SwiftUI content is laid out at a fixed height, pinned to the window's top (`PanelController.sizeContent()`); the panel is built and drawn once off-screen just after launch (`PanelController.warmUp`, `panel` is a `lazy var`) so the first ⌥ Space is as quick as later ones, and the window only shows as much as the card needs: it grows at once and shrinks after the card's animation. Don't make the hosting view the window's content view again; a window resize would then resize the layout mid-animation and drop the card by half its growth.
- **Behavior.** Return sends. Tab no longer sends (it did the same as Return); instead it opens the card for writing a note to send with the question (`ChatSession.writeState`, `TypedStateCard`), in any mode — the same card Decision's Write It row opens, so text is one more piece of context for an LLM or agent as well as what a decision is about — and ⌘Return sends from that card, where plain Return makes a new line (handled in `PanelController`'s key monitor, ahead of Insert Answer). The card takes the keyboard as it opens, whoever opens it (Tab, Write It, Add Text, a preset), through `PanelLayout.stateFocusRequest`, which `ChatPanelView` answers a moment later, since a focus set in the update that inserts the card never took; Tab from the card goes back to the input, with the cursor after its text, and takes an empty card away with it (`ChatSession.leaveTypedState()`), so Tab closes what Tab opened. In LLM and Agent modes the card also opens by itself as the question comes to end in a colon (“Fix the grammar:”, `ChatSession.endsInColon`, from `draft`'s `didSet`), when the draft holds nothing to work on (`hasNothingToWorkOn`), as a preset does; the keyboard stays in the input then, and a card closed by its cross stays closed while the colon stays. Esc puts away the shortcut picker, closes a panel of actions (or backs out of its confirmation), folds away the What's New notes, stops, then starts a new chat, then closes. Closing the window only hides it: it fades out over `PanelController.fadeOut` as the card sinks a little, and is ordered out by the clock, not the fade's end (⌥ Space during the fade turns it around; Insert Answer closes without it, since its paste needs the keyboard back in the app in front at once); it opens the other way around, fading in over `fadeIn` as the card rises into place (`PanelLayout.isShown`, which `PanelRoot` scales from the top and offsets; only the fade with Reduce Motion), because the system's utility-window behavior showed and hid it in a cut. Inside the card, a chat's first question brings the conversation in at its own size, unmeasured until then (`conversationHeight` is 0 between chats), so the card grows to it with its animation instead of jumping once it is measured; within a turn the thinking line fades into the answer's first words, Show What Changed and Show Answer fade one into the other in place (the same text, so the changed words light up in their colors), and an agent's ask, its tools, and the files it hands over fade in, while a streaming answer's words come as they are. The conversation follows its end as it grows only while the reader is there (`followsEnd` in `ChatPanelView`): `onScrollGeometryChange` tells a scroll of the reader's from growth, since only the reader moves the offset while the content's and the container's sizes stand still. Scrolling up lets go, so a long answer can be read from its start while it streams, and scrolling back to the end, or asking, takes hold again. Don't scroll to the bottom on every change of height again: that pulled the reader down with each word, and once more when the follow-ups came (`ConversationScrollTests` holds it on the real panel). Streamed text joins its answer in batches, at most every `ChatSession.textInterval` (50 ms; `hold(_:)` and `addHeldText()`), since an answer is laid out again each time it grows: an answer's first words go in at once, in the thinking line's place, and the rest with whatever came meanwhile, always ahead of a tool, an ask, or a file that followed it in the stream, and all of it before the answer ends, fails, is stopped, or its chat is left. Every chat has its own time, `ChatSession.chatLifetime` (30 minutes, no setting): a message or the end of an answer starts it over, unless it has more left, and a game waiting for its first move has none yet. It keeps running in Recent Chats, and reopening the chat keeps the time it has left (a chat already out of time goes instead). When it runs out, the chat goes with its workspace without passing through Recent Chats; what is typed in the input stays, and an answer still coming holds the open chat until it ends. `ChatSession.expireChats(now:)` does it, at each deadline and when the window opens, in case the Mac slept through one. The timer (`ChatTimer`) is a neutral glass capsule under the card's bottom right, lined up with the footer's actions, in the same bottom margin as the capsules on the left: minutes left, then seconds in the last one. It takes no click; +5 min and +30 min to its left (`ChatTimer.extraMinutes`, `ChatSession.addTime(minutes:)`) add to the time left, which a message then never cuts back to 30 minutes, and Recent Chats and reopening keep. As they do, the capsule shines (`Shine`, one `KeyframeAnimator`): its minutes roll up, it swells a little on its own glass container and settles with a spring, its glass flushes pink and fades back, a highlight sweeps across it, and the timer symbol bounces; with Reduce Motion only the pink and the roll remain. From "5 min left" (`ChatTimer.warningMinutes`) it looks like the mode toggle's chosen segment: a pink symbol and a semibold label in the primary color, in glass with the same faint pink tint. Before there is a chat (no turns and no game), the same spot holds pills instead (`CostNudges`): one for the LLMs and one for the agents, each its mode's symbol from the toggle and what that kind has cost today, the calendar day's cost in the usage ledger (`UsageLedger.cost(of:onDayOf:)`), once either has cost a tenth of a cent (`UsageInsights.leastMoney`, the least `money` writes as a number; a kind below it reads $0), and until then one pill alone, a dollar sign and “$0 today”. There is nothing to set: the amounts of Settings › Usage › Daily nudge were removed on purpose, so don't bring them back. They are neutral glass with a pink symbol, each in a glass container of its own, sized to their labels whatever width they are offered (a label that wrapped once moved the row 60 points off the card's edge), and take no click, so no button of theirs lies where the timer's are while one row fades into the other, even in the hidden window when a chat runs out. The pin has no countdown, and Settings › General › Start a new chat was removed on purpose; don't bring them back. Capsules under the card's bottom left, lined up with the buttons above its top left (`Announcements`, drawn in the window's bottom margin, which is `Announcements.roomBelow` taller while one shows), announce updates and a crash. A capsule whose state changes, the update's from found to staged, the crash's from Copy Diagnostics to Copied, is one view whose label changes, never one view for each state: two of them cross-fading while the window was hidden hung Meraline for good on macOS 27, two focusable buttons on one spot that SwiftUI's key view loop never settled over, and `AnnouncementsTests` lays the real panel out under a watchdog to keep it so. After Meraline quits unexpectedly, the next launch finds macOS's report of it in ~/Library/Logs/DiagnosticReports (or its Retired folder), newer than the launch before (`CrashNotice`, which keeps only the launch date in UserDefaults), and a Copy Diagnostics capsule copies the report with a Crash section, says Copied, and goes; its cross hides it too, and the next launch never offers the same crash again. The section keeps only the exception, the termination, the Swift runtime's words up to their first colon (none if they quote something) or an uncaught exception's name (never its reason), Meraline's image UUID and load address, and the crashed thread's frames, so the diagnostics still hold no question, answer, or key; Settings › About › Copy Diagnostics includes it for the rest of that run. The sparkle's panel offers Copy Diagnostics at any time, crash or not, through the same `CrashNotice.copyDiagnostics(of:preferences:updates:)`, and the crash's capsule then shows only to say Copied: one capsule whose label changes, never a second one. Before any copy, `Diagnostics.redacting` writes the home folder as `~` and takes out any API key set in Settings, across the whole report, log lines included. After an update, What's New opens the notes under the input, with their screenshots (`ReleaseNotes.Block.picture`, fetched when the notes open through an ephemeral session and kept in memory), until its cross or Got It hides it; `WhatsNew` keeps the version and Sparkle's notes in UserDefaults so the next update brings it back, and there is no What's new window. Beside it, an update Sparkle found (Update Available, which opens Sparkle's window) or staged (Restart to Update) shows until its cross hides that version; `UpdateNotice` keeps the hidden version in UserDefaults, so only a newer update brings it back. The menu bar item and Settings › Software Update offer the update regardless. On the first launch the window opens on a shortcut picker (`ShortcutSetup`, until `hasChosenShortcut` is set) before the shortcut is ever pressed: it checks whether macOS uses ⌥ Space, whether Meraline could register it, and whether ChatGPT, Gemini, Copilot, Raycast, Alfred, SpotAsk, or Seer is running or installed, then offers Keep or suggestions that skip whatever looks taken. A suggestion is registered under `shortcutTrial` until it is pressed, which keeps it, or Use This Shortcut. Esc or a click elsewhere keeps ⌥ Space and leaves a capsule under the empty input that opens Settings › General on the recorder, until the shortcut changes or its cross hides it. The row under the input (`ModeBar`) holds the LLM, Agent, and Decision toggle on the left (⌘1, ⌘2, ⌘3, which give way to the presets while an answer is ready, and which `PanelController`'s key monitor matches by the key's place, `PanelContext.modeSwitches`, never a SwiftUI `keyboardShortcut`, which follows what the layout types and so needed Shift on a Czech keyboard) with the privacy badges beside it and, on the right, the games behind a controller, which give way in Decision mode to the answers the next question picks from (`DecisionAnswersBadge`, each in a glass container of its own so its fade reaches its glass), and Recent Chats behind a clock that shows their count. The controller opens and closes the games; one tray is open at a time, and `PanelLayout` remembers which while the window is hidden, in memory only. `GameTray` lays out every frame of its spring from one animated `openness` (the capsule's width, how much of the row shows, each game's fade), so nothing is inserted or removed while it moves; keep it that way, since inserted views land ahead of the glass. The footer under a chat shows one primary action (Stop, Copy Answer, Ask Again after an answer failed partway, or a game's Hint or End Game) and Actions ⌘K; a failure's banner offers Try Again (`ChatSession.tryAgain()`, by `failureRetry`: Ask Again for an answer cut short, or sending the question that came back to the input), unless it is a setup problem, which gets Open Settings; the rest live in a panel of actions, as do the sparkle's providers and the clock's recent chats. Beside Ask Again, the chat's panel rewrites the last answer (`ChatSession.rewrite(_:)`: shorter, longer, simpler, more concrete, a bullet list): the provider in use gets the conversation and the rewrite's instruction, and the new answer takes the old one's place under the same question, so follow-ups and the next rewrite read it; the instruction never shows. A rewrite stopped or failed partway puts the old answer back. - **Decisions.** The third mode, Decision (⌘3), asks a System One model, one that writes nothing: TypeSafe's Jev directly (`Provider.typeSafe`), or any of the `text->decisions` models OpenRouter serves over the same contract (`Provider.openRouterDecision`, whose key is OpenRouter's under LLMs, one Keychain item through `Provider.keyAccount`, and whose `suggestedModels`, `Provider.openRouterDecisionModels`, are the ones run live with Meraline's own requests, Respan's left out since they read only a conversation transcript), or one Ollama runs on this Mac (`Provider.ollamaDecision`, Ollama 0.35 or newer: no key, off until Settings turns it on like Ollama under LLMs, `Provider.ollamaDecisionModels`, Bespoke Labs' Nimble and Together's Tev1, which the pane's footer says to pull, free in the ledger through `Provider.runsOnThisMac`, and a chat model it is asked for gets Ollama's own readable error); `Provider.decisionModels` lists the three under `ProviderKind.decision`. `DecisionClient` posts one request to `POST /v1/systemone`, at TypeSafe, at OpenRouter, or at Ollama, with the key as a bearer token when the provider takes one, and reads one JSON reply, never a stream, into a `Decision` (`StreamOutput.decision`), which `Turn.decision` keeps beside `answer`, the decision in words (“Yes (82% confident)”, `Decision.summary`) for Copy, Insert, Recent Chats, and the transcript's Markdown. Jev takes no system prompt (`ProviderKind.prompted` leaves Decision out of Settings › Prompt and `SystemPrompt.allCases`) and keeps no conversation: the request's state is the chat's texts, every turn's `selections` and the draft's (`ChatSession.decisionState`), so a follow-up asks about the same texts anew, and the quote shows once, on the question that brought it. Text is optional: with none, `makeDecisionRequest` sends the question itself as the state, so a question that stands on its own is decided as it is; while there is none (`needsDecisionState`), `DecisionStateRow`, between the input and the mode row, suggests adding some, and its Write It puts `TypedStateCard` in its place, for `ChatSession.typedState`, which goes with the question as `SelectedText.typed`, quoted as Context, a `<text>` block for any other provider; pictures wait with a Switch to LLM row (`pictureNotice`) and files with Switch to Agent, the screenshot button is unavailable, the clipboard button reads text only (`ClipboardContent.readText`), and Finder's selection brings nothing. The answers are Yes and No (Jev's `noul` question) unless the question names its own after its last question mark or colon, with `/` between them (`choice`, no descriptions) or `<` for levels in order (`score`, at most 10; more go as a set): `DecisionAnswers.split` reads them off, Settings › Prompt › Decisions sets the ones a question that names none picks from (`Preferences.decisionAnswers`, written the same way, Yes / No until changed), and the badge at the games' place shows what the draft picks from (`draftAnswers`). Beside it, a switch (`DecisionScopeToggle`, `Preferences.decisionScope`, kept in UserDefaults) decides about the whole text or each of its words or lines (`DecisionScope.items(in:)`: words split at spaces with the punctuation around them left off, lines trimmed, each once): the items go in the state and each gets a question of its own, named `item_<n>` with the question, `items[n]`, and the item as its instructions, `DecisionScope.batchSize` (100) a request, and each reply grows the turn's `DecisionBatch`. Ollama's models read every question of a request in each prompt, and a prompt takes at most 2,050 tokens (the `num_ctx` they ship with, which a request can't raise), so Ollama gets `Provider.questionsPerRequest` (8) a request, trimmed (`Provider.trimsDecisionState`, `DecisionRequest.body(model:itemsFrom:count:trimmed:)`): the state holds only the batch's items, which the questions name from 0, and the texts only up to `DecisionRequest.trimmedTextLimit` (2,000 characters), while the questions keep their names by their place among all the items, so the reply reads the same; a whole text past the prompt's size gets Ollama's own error, which names the tokens. Eight fits lines of sixty words and takes about as long an item as a bigger batch, since the tokens grow with the batch squared. Jev and OpenRouter get every item and the texts (`StreamOutput.decisions`, `Turn.decisions`), so `BulkDecisionCard` fills as they come, then groups the words or lines by answer, Not Sure last and each answer's surest first (`DecisionBatch.groups(unsureBelow:)`, which `summary` follows), every answer folded to its header and count until a click on it opens its words or lines in place (`PanelLayout.openDecisionGroups`, by turn and answer, in memory only, so a reopened chat keeps what was open and a new decision starts folded), and `answer` sums them up in Markdown. At most `DecisionScope.itemLimit` (1,000) items a question; past it the draft waits with a Whole Text row (`bulkNotice`), and a text with no items is decided about whole. Every item counts as a decision in the ledger. A click on the switch (`ChatSession.chooseScope(_:)`) also puts a note under the cards that says what the chosen scope decides about, the whole text too when it was switched back to (`DecisionScopeNote`, `ChatSession.explainedScope`, in memory only): it goes with the question, with the chat, or at its cross, and never shows by itself. `DecisionCard` draws the answer: a check on green glass for Yes, a cross on red for No (`NSColor.addedText`, `removedText`, as Show What Changed), ringed by the confidence, “82% confident” beside it, and every answer's probability under it in the answers' order; a list of your own gets a check tinted by Jev's confidence (amber when it is moderately sure, green when very sure), levels in order a scale (`ScaleRow`) with a marker where Jev placed the text, between two levels when it isn't sure, and each level's share under it, and under `Preferences.unsureBelow` (Settings › Prompt › Decisions, 50% by default) the card says Not Sure with a question mark and the lean. The confidence is Jev's own, 0 to 1, which for two answers is twice the winner's probability less one (`Decision.confidence(over:)` when a reply carries none), and the check, the cross, and the words carry the meaning, so the colors are only a help. No follow-ups are suggested for a decision, and no rewrite, preset on the answer, Show What Changed, Tear Off, or zoom is offered; Ask Again asks about the same texts. In Decision mode the Context card's header has a Live switch (`LiveDecisions.isOn`, in memory, off in every new chat since every pause in typing then asks the model; `ChatSession.reset()` calls `liveDecisions.reset()`, after the draft has taken the switch's state to Recent Chats, and the switch itself clears the presets and kept questions when turned): on, `LiveDecisions` (owned by `ChatSession`, told what to ask by `refreshLiveDecisions()` from the draft's, the texts', and the card's `didSet`s and the panel's `onChange(of: session.liveAsk)` for the mode, provider, and presets) asks the decision provider in use about the chat's texts and the card's after each pause of `LiveDecisions.debounce` (400 ms) and at the latest `maxWait` (1 s) after typing began, so a long sentence is decided about as it grows, in one request that carries every question at once (`DecisionClient.decide(_:about:settings:provider:)`, `DecisionRequest.body(model:state:questions:)`, `Provider.questionsPerRequest` a request for Ollama), one request in flight and the latest change queued behind it, and shows each answer on a glass capsule under the text (`LiveDecisionStrip`, each capsule a `GlassEffectContainer` of its own: green glass for Yes, red for No, plain for Not Sure, for one of your own answers, and while off, pink until its first answer, and never a shade by confidence, three looks only; nothing in it rotates): the questions kept from the input first (`KeptQuestion`, `LiveDecisions.keptQuestions`: the plus on the input's capsule keeps its question and empties the input, `ChatSession.keepLiveQuestion()`, a click turns one off and on, its cross removes it), then the input's, always, so keeping it leaves the capsule in its place and moves no other, then each of Decision's presets, which a click on its capsule turns on or off (`LiveDecisions.enabledPresets`, `ChatSession.toggleLivePreset(_:)`), a question asked twice over going once. No turn is made and nothing is kept on disk: an answer stays in memory while its text and question stay, whichever capsule asks it (so a preset turned on asks only itself, off and on again asks nothing, and a kept question takes the input's answer with it); while a newer answer is on its way the last one stays on its capsule as it is (`isStale` says so for accessibility), never a spinner or a fade in the words' place, since the capsules change together and the Live switch shows the one loader for them (`isWorking`, a mini spinner in the bolt's place), and a reply about an earlier text still lands and shows until the next; the capsules carry no icon before the title (a pink icon beside a red No read wrong); a failure shows in one line under the capsules until the next change. The ledger counts them as `decisions` and `liveDecisions`, with the model's tokens, never as questions or answers. Games are never played against Jev: the tray fades in Decision mode, `startGame` switches to the LLM's or the agent's mode, and `gameProvider` falls back to their default. The ledger counts `decisions` and `unsureDecisions`, never an answer's name, prices Jev at TypeSafe's list price (`ModelPrice.jev`, which OpenRouter's list of models doesn't carry) and OpenRouter's decision models at what each reply says it cost (`usage.cost`, into `TokenUsage.cost`), Jev's price for tokens no one priced, and the cost pills get a third capsule. `meraline://ask?mode=decision` and `meraline://mode?mode=decision` name the mode (`agent=1` still works), and `meraline://mode` alone goes around the toggle (`ProviderKind.next`).
- **Links in answers.** `AnswerLinks` turns a path in an answer into a link only when it names a file or folder on this Mac, and a `meraline://` URL only when it has a route. A path counts when it is absolute, starts with `~/`, or, in an agent's chat, is relative to its workspace (`answerWorkspace` in the environment) and has a slash or an extension. It may take in up to `wordsWithSpaces` more words, or a whole code span, for names with spaces, and a line number after it (`App.swift:42`) stays in the link. A link the model wrote to a path leads to the file too. Code blocks are left alone. Links are found each time an answer is drawn, on the main thread, and kept nowhere, so paths on servers and autofs (`remoteMountPoints()`) are never looked at: a look there can wait a minute. A click opens by a handed-over file's rules (`PresentedFile.opening(of:isFolder:)`: nothing runs, scripts open as text, apps are only shown in Finder), marking a workspace file as downloaded first; ⌘-click, read off the click itself, shows it in Finder. A `meraline://` link runs its route in this Meraline without its `send` (`AutomationRoute.withoutSending`), so a question the model wrote waits for Return. Each answer in a torn-off note keeps its chat's workspace for them.
- **Privacy signals.** The panel doesn't label providers that answer on this Mac; the "on this Mac" badge was removed on purpose, so don't bring it back. Hide from Screen Sharing (`Preferences.hidesFromScreenSharing`, off by default, in Settings › General › Privacy and the sparkle's panel, shown as a crossed-out eye beside the mode toggle) sets the panel's `sharingType` to `.none`. Since macOS 15, captures of the whole display through ScreenCaptureKit (QuickTime, OBS, some video-call apps) show the window anyway, so copy never promises it is invisible. Settings › General › Privacy can also forget every chat when the Mac or its display goes to sleep (`Preferences.forgetsChatsOnSleep`) and when the screen locks or another user takes the screen (`forgetsChatsOnLock`), both off by default. `AwayWatcher`, which `AppDelegate` keeps, hears NSWorkspace's sleep and session notifications and the distributed `com.apple.screenIsLocked`, and `PanelController.forgetChats()` forgets as quitting does (`ChatSession.forgetAll()`): the open chat with what is typed and offered for it, Recent Chats, their workspaces and live agents, torn-off answers, and any panel of actions. The window stays as it was, and so does the games' tally, which holds no word of a chat. Shutting down, restarting, and logging out quit Meraline, which forgets everything anyway, so they need no setting.
- **Agents and MCP.** Settings groups providers as LLMs (the services) and Agents (Claude Code, Codex, OpenCode). Agents may use the MCP servers set up in them. Meraline lists those by asking the agent (`<agent> mcp list`), never edits an agent's configuration, and keeps only server names in UserDefaults (they are settings, not chat content). A run names its servers one by one, because claude's allow rules need a server name and `mcp__*` does nothing, and turns off the ones off in Settings through the agent's own overrides (`--disallowedTools mcp__<server>`, `-c mcp_servers.<name>.enabled=false`, `OPENCODE_CONFIG_CONTENT`). What an agent is asking shows while it answers, and the tools an answer used sit under it. Once the answer is finished, a click on a tool's capsule (`ToolTrail`) has the provider that answered say in one line under them why it used that tool (`ToolReason.explain(toolAt:of:in:provider:settings:instructions:stream:)`), from the chat up to that answer, the answer, and the capsules' own words, since the trail keeps no tool's input: Claude Code in Why?'s short run, any other provider in a request of its own with its settings less the web and MCP servers and no workspace. It is never another provider, so the chat goes nowhere it didn't go already, and a turn whose provider isn't ready any more offers none. The one Why? prompt serves both, and a reason is kept only by the trail's view state. An agent works in the chat's workspace: Claude Code has its file tools, Bash, and its skills there and asks over stdin and stdout (`--permission-prompt-tool stdio`, `control_request` in, `control_response` out) before a write, a command it doesn't judge read-only, or a skill, or when it has a question (`AskUserQuestion`), which the panel shows as a card with Allow and Deny (and Why?, which asks Claude Code for its reason in one line in a short run of its own: `ToolReason`, haiku, no tools, no MCP servers, no thinking) or the question's choices, which ⌘1 to ⌘9 pick for the first question not yet answered (`PanelContext.promptChoices`, ahead of the modes' and the presets' digits while the question waits; the key monitor sets `PanelLayout.promptChoice` and the card takes it as a click, since the picks are the card's own state); Codex runs as `codex app-server` in ephemeral threads with a `workspace-write` sandbox and approvals off, so it cannot ask; OpenCode's run mode turns its own asks down, which the panel reports. Each ask and how it was settled stays with the turn (`Turn.prompts`). Claude Code's stdin stays open until its `result`, never just a `message_stop`: every message ends in one, the one that calls a tool too, and closing stdin then turns down the ask still waiting. Claude Code and Codex stay running for their chat (`LiveAgents`, keyed by the workspace, at most `LiveAgents.limit`, ended after `idleLifetime` unused, by Stop, or with the workspace) and start ahead when the window opens in Agent mode (`ChatSession.prewarm()`): a follow-up sends only the new question, and anything else, Ask Again, a rewrite, another provider's answer in between, starts over from the transcript, in a new process or a new Codex thread. Nothing is resumed from disk. Every chat with an agent (not a game) also gets Meraline's own MCP server (`PresentFilesServer`), whatever Settings says about the others, and a paragraph of the system prompt on when to use its one tool, `present_files`, which hands files to the person. The server is Meraline's own executable started with `--present-files-server <workspace>` (`MeralineApp.main` checks for it before anything else starts), so there is no helper to sign; it goes in through `--mcp-config` and `--allowedTools`, `-c mcp_servers.meraline.*` after the overrides that turn servers off, and `OPENCODE_CONFIG_CONTENT`. It only checks the paths, inside the workspace with symlinks resolved (`PresentedFile.handOver`), and answers; the panel reads the same call from the agent's stream (`StreamChunk.presented`) and checks it the same way, so it shows exactly what the agent was told it handed over. The files show as cards under the answer (`Turn.presentedFiles`) with Open in the app the Mac opens them with, Show in Finder, Copy, Save to Downloads, and dragging out, and the chat's actions offer the same for the last ones (⌘O, ⌘S). A picture shows itself on its card instead of its icon (`PresentedFile.picture(at:)`: read off the main thread, at most 1,200 px on its longer side, kept only in the card), up to `PresentedFileCard.pictureHeight` and never above its own pixels; a click shows it larger, up to `enlargedPictureHeight`, inside the window. Not Quick Look: its window would take the keyboard and close the panel. A page (HTML) or a Markdown file shows a glass preview strip there instead (`FilePreviewStrip`), up to `FilePreviewStrip.height`, fading out where the file goes on; a click shows more, up to `enlargedHeight`. Markdown's first lines (`FilePreview.markdown(at:)`: at most 16 KB and 200 lines, front matter left out) are drawn by `MarkdownView`. A page is drawn by an `InertWebView`, which no click, key, scroll, or pointer reaches, and loads only once scrolled into view: the page's scripts off (`allowsContentJavaScript`; only Meraline's own script runs, to measure it and hide its scroll bars), a content rule list that blocks every load but `file:`, `data:`, and `about:` (compiled once into WebKit's store, which holds only the rules), read access to the workspace alone, no navigation past its own file, a non-persistent data store, and no media playing by itself. Keep it so: an agent's page can come from anywhere, and looking at it must never tell a server. A file is marked as downloaded (quarantined) before it leaves for another app, and Open never runs anything: scripts open in the plain-text app, and apps, programs, and files that run or install something (`.terminal`, `.mobileconfig`, …) are only shown in Finder.
- **Releases.** Version comes from the tag (a suffix, as in `v1.8.0-beta.1`, makes a beta, and `UpdateChannel(version:)` reads the running version the same way for Settings' chip), the build number is the commit count, and a release is always signed and notarized. The release's `CHANGELOG.md` section shows its new features with screenshots from `docs/screenshots`, linked at the tag (see docs/releasing.md). Take a picture with `scripts/showcase.sh` whenever its state can be scripted: add a scene to `ShowcaseTests` with a `ScriptedModel`, seeded dice, or `DemoUsage`. Before changing an animation, record it with `scripts/clips.sh --out <before>` (`ClipTests`, each a scene `ShowcaseStage.recordPanel` films with ScreenCaptureKit while the scene drives the panel), record it again after, and put the two side by side with ffmpeg, so the change can be judged; add a scene for an animation the clips don't cover. With `--backdrop <png>` the picture covers the whole screen behind the panel, which sits where the promo's films have it (`ShowcaseStage.filmTopLeft(top:)`), the films' 16:9 region is recorded (`ShowcaseStage.filmRegion`), and the scene's markers (`ClipMarks`, on the capture's own clock) go into `name.json` beside the clip, so a scripted scene drops straight into the promo project's films (`ClipTests.live`, the Live decisions demo, with scripted typing and a decider written to the words). It never clicks or types and runs while someone works, only taking the keyboard for about a second per picture after 5 s without input, because a window draws its active look (pink glass tints, the text cursor, colored traffic lights) only while it has the keyboard. Its pictures match `scripts/screenshots.sh`'s: the same gradient, sizes, and file names. Keep that script for what needs a real provider, an agent, or clicks, and never drive the UI while the Mac is in use. A plain offscreen render (`cacheDisplay`) draws no glass, so it only checks layout. Never re-introduce `codesign --deep`. The layout numbers in `assets/dmg/background.html` and `scripts/lib/dmg.sh` must change together.
