# AGENTS.md

Meraline is a macOS 26 menu bar app for quick, ephemeral AI chats: press ⌥ Space, ask, read the streamed answer, let it go. Swift 6, SwiftUI plus AppKit, no sandbox, hardened runtime. This file is the entry point for agents and contributors; [CONTRIBUTING.md](CONTRIBUTING.md) is the human-facing version.

## Build, test, run

The Xcode project is **generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)** from `project.yml` and is gitignored. Re-run `xcodegen generate` after adding or removing files; every script does it for you.

```sh
scripts/dev_run.sh                  # Debug build, relaunch from DerivedData, logs in /tmp/meraline.log
scripts/test.sh                     # full test suite (Swift Testing), xcbeautify output when installed
scripts/test.sh HistoryTests        # one test struct
scripts/test.sh --e2e               # also run the installed claude, codex, and opencode for real
scripts/install.sh                  # clean Release build into /Applications and launch it
scripts/clean.sh                    # remove build/ and DerivedData
scripts/screenshots.sh --wait-idle  # README screenshots of every feature, dark and light, once the Mac is idle
scripts/release.sh 1.2.0 --adhoc    # the whole release pipeline without credentials (see docs/releasing.md)
```

Dependencies are pinned to exact versions in `project.yml` (Sparkle, KeyboardShortcuts, EventSource). Bump them there, deliberately.

A Developer ID certificate is optional. `dev_run.sh`, `test.sh`, and `release.sh --adhoc` sign ad-hoc when the certificate is missing; only `install.sh` and real releases need it.

## Layout

| Path | What lives there |
| --- | --- |
| `Meraline/App/AppDelegate.swift` | Entry point, menu bar item, main menu, hotkey, `meraline://` URL routes, What's new after an update |
| `Meraline/Panel/` | The floating non-activating panel (`PanelController`), its SwiftUI content (`ChatPanelView`), and the row under the input with the mode toggle and the game buttons (`ModeBar`) |
| `Meraline/Chat/` | `ChatSession` (in-memory turns, draft, streaming, recent chats, and the game engine), `ImageAttachment`, and `ThinkingStatus` (the lines the panel murmurs while waiting for an answer) |
| `Meraline/Games/` | The games behind the controller buttons under the input: `Game` (the list, the `GameRules` protocol, shared parsing) and one file of rules per game |
| `Meraline/Providers/` | Provider list and settings, request building, HTTP streaming (`LLMClient`), command-line tools (`CommandLineClient`), stream decoding, and the agents' MCP servers (`MCPServer` lists them by asking the agent, `MCPServerRegistry` keeps the list) |
| `Meraline/Settings/` | The System Settings-style window and its panes |
| `Meraline/Support/` | `Preferences` (UserDefaults + Keychain), `Updater` (Sparkle), `Log` and `Diagnostics`, `Brand` colors, `Keychain` |
| `Meraline/Resources/` | `Info.plist` (generated from `project.yml`), asset catalog, the Icon Composer icon |
| `MeralineTests/` | Swift Testing suites; `Preferences` takes an injected `UserDefaults` suite and `SecretStore` so tests never touch the Keychain |
| `scripts/`, `assets/dmg/`, `docs/releasing.md` | The release pipeline and the disk image; `docs/diagnostics.md` covers logging |

## Hard rules

- **Nothing on disk.** Conversations, drafts, images, and recent chats stay in memory. Do not add persistence for them. The one folder an agent gets is the chat's workspace (`ChatWorkspace`, an empty temporary folder per chat): it holds only what the agent writes there and goes with the chat or at quit.
- **Secrets go through `SecretStore`.** API keys are Keychain items; never put them in UserDefaults, logs, diagnostics, or URLs.
- **Log through `Log`, never `print`.** `Log.<category>.info(...)` writes to `os.Logger` and the in-memory buffer that feeds the diagnostics report. Log providers, models, paths, and error descriptions; never questions, answers, or keys.
- **Swift 6, strict concurrency, `MainActor` by default.** Networking and parsing types are `nonisolated`. Sparkle's KVO and delegate callbacks must read their arguments rather than main-actor state.
- **Design.** The base is neutral glass: white, black, gray, graphite accent. Pink appears only as an accent (text cursor, the sparkle in the input row, toggles, the active pin, a faint glass tint on buttons). Never solid pink buttons or strong pink backgrounds. The logo is the sparkle character with a face; do not change it. The panel draws its own rounded shadow and keeps the window shadow off.
- **Behavior.** Return or Tab sends. Esc stops, then starts a new chat, then closes. Closing the window only hides it. The row under the input (`ModeBar`) holds the LLM and Agent toggle on the left (⌘1, ⌘2) and the games on the right. Each mode keeps its own provider (`Preferences.mode`, `defaultProvider(for:)`), and the sparkle menu lists only the ready providers of the current mode, plus Recent Chats; there is no model switcher in the panel. Games are a mode of `ChatSession`, started from their buttons in that row, and the model always moves first. A game's rules work everything out from the turns, so a game keeps no state of its own; answers the model hides after a `|` in its reply stay hidden until you have played, except that Hint in the footer shows a game's hints for your move one at a time (Rhyme Duel's are the rhymes the model hid for its last word). Each game has its own system prompt and never touches the prompt in Settings, lives only in memory like any chat, and Esc or End Game ends it. A move that breaks the rules comes back to the input and costs nothing.
- **Agents and MCP.** Settings groups providers as LLMs (the services) and Agents (Claude Code, Codex, OpenCode). Agents may use the MCP servers set up in them. Meraline lists those by asking the agent (`<agent> mcp list`), never edits an agent's configuration, and keeps only server names in UserDefaults (they are settings, not chat content). A run names its servers one by one, because claude's allow rules need a server name and `mcp__*` does nothing, and turns off the ones off in Settings through the agent's own overrides (`--disallowedTools mcp__<server>`, `-c mcp_servers.<name>.enabled=false`, `OPENCODE_CONFIG_CONTENT`). What an agent is asking shows while it answers, and the tools an answer used sit under it. An agent works in the chat's workspace: Claude Code has its file tools there and asks over stdin and stdout (`--permission-prompt-tool stdio`, `control_request` in, `control_response` out) before a write or when it has a question (`AskUserQuestion`), which the panel shows as a card with Allow and Deny or the question's choices; Codex runs `--sandbox workspace-write` and cannot ask; OpenCode's run mode turns its own asks down, which the panel reports. Each ask and how it was settled stays with the turn (`Turn.prompts`).
- **Releases.** Version comes from the tag, the build number is the commit count, and a release is always signed and notarized. Never re-introduce `codesign --deep`. The layout numbers in `assets/dmg/background.html` and `scripts/lib/dmg.sh` must change together.
